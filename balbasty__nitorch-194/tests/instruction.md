# Issue

**Title:** FIX(orient, vopt): optional .lta, SVF output extension, 3D voxel size

## Description

Part of #171. I reproduced each bug before fixing it.

1. **`orient` always wrote an `.lta`.** `main.py` filled in a default transform name whenever the input was a file. Now:
   - with no `-t`, no `.lta` is written;
   - a bare `-t` writes `{dir}{sep}{base}_to_{layout}.lta`, handled in the parser the same way `reorient` does it;
   - `-t FILE...` writes to the given names.

   Before this fix, a bare `-t` crashed with "Empty sequence".
2. **`vopt`'s default output had the `.lta` extension**, and saving a velocity field there crashed. The default is now `{dir}{sep}{label}_optimal.nii.gz`, and the help is updated.
3. **`vopt`'s `voxel_size` had 4 components**, because it was computed over the whole 4×4 affine. It now uses `spatial.voxel_size(aff)`.

**Docs**
- `orient.md`: removed the "even if you do not ask for it" caveat, and updated the synopsis and the `-t` row.
- `vopt.md`: replaced the "Always pass `-o`" warning and updated the default.

**Tests**
- The new `nitorch/tests/test_cli_orient_vopt.py` has 5 tests: the three `orient -t` cases, `vopt`'s default output name, and `vopt`'s voxel size and outputs, with the optimiser replaced by a fast fake.
- Before the fix 4 fail and 1 passes. After it, all pass, together with `test_cli_transform_tag.py` (11 passed).
- A real `vopt` run on 8³ fields wrote `{a,b,c}_optimal.nii.gz` with shape (8,8,8,3).

**Behaviour changes**
- `orient` writes no `.lta` unless `-t` is given.
- `vopt` writes `.nii.gz` by default; before, it crashed.

**New bugs noticed, not fixed here** (added to #171):
- `spatial/_svf_optimal.py` `fit_unweighted` calls `svf.setdefault((b, a), -v)` while iterating over `svf.items()`. A pair given in one direction only, without `-w`, then crashes with "dictionary changed size during iteration". This breaks the second example in `vopt.md`.
- `io/loadsave.py:360` calls `klass.savef_new`, but `LinearTransformArray` only defines `save_new`.
