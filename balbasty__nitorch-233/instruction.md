# Issue

**Title:** FIX(core.cli): reject unknown options; name invalid values and their choices

## Description

Part of #171. This replaces the `optinorm`-specific fix in #231 with a general one in the shared parser, following your review there.

**Affected commands:** every command that uses `CommandParser`: denoise, metrics, smooth, epic, estatics, greeq, topup (fit/apply, through its subclass), affreg, meanspace, optinorm, register, resize, simplereg and uniseg.

**1. An invalid value was reported as "Not enough arguments".** When filling its required values, `Option.parse` treated a value that failed conversion or validation the same as a missing one. `Validations.choice` also did not keep its choices, so nothing could list them.
- `Validations.choice` now stores its choices on the returned check, which is still a plain predicate.
- A value that is present but rejected now gives `Invalid value 'foo' for --affine; choose from {rigid, similitude, affine}`. For options without choices, such as `--bins abc`, the message has no list.
- A value that is really missing (end of the arguments, or the next tag) keeps `Not enough arguments for option X: expected at least N but got M.`, followed by ` Choose from {…}.` when the option has choices.
- Reproduced on `optinorm --affine foo`, `epic -d foo` and `topup fit -l foo`.

**2. Unknown options were swallowed.** Positionals and `*`/`+` options consumed anything that was not one of the tags at their own level. So `--nope` became an input file (optinorm, epic), a value of `-p` (topup apply), an echo (estatics), or a fixed image (register `@@fix`).
- Right after the help check, `CommandParser.parse` collects every known tag at every depth: options, groups, `NamedGroup` sub-options and nested groups.
- Any argument that `istag` treats as a tag and that is not known now raises `Unknown option --nope`.
- Negative numbers, a lone `-`, `-2d` and `@` group tags are still values, and `-h` still shows the help even when unknown options are present.
- `CommandParser(..., allow_unknown_options=True)` keeps the old behaviour. No command needs it: topup's subclass, the fit/apply dispatch, the estatics/greeq groups, register's nested groups and epic's `-p -` were all checked.

**⚠️ Behaviour changes users will see**
- Dash-prefixed arguments that are not options are now errors everywhere. This covers `--tag=value`, a bare `--`, and file names such as `-odd.nii`, which must now be written `./-odd.nii` (the docs already advised this).
- Invalid values say "Invalid value …" instead of "Not enough arguments".

**Docs:** a writer subagent updated `docs/cli/conventions.md` in three places:
- the "option takes all the values" section;
- the "tag vs value" section;
- the errors section, with the new messages and a note that hand-written parsers may word errors differently.

No reference page had a caveat about this.

**Tests:** the new `nitorch/tests/test_core_cli_parser.py` has 39 tests. On small synthetic parsers they cover:
- valid, invalid and missing choices, including inside a group;
- an invalid converted value;
- unknown long and short options in four positions, and options inside groups recognised as known;
- negative numbers, a lone `-`, help, and the opt-out.

On real commands they cover:
- topup: an invalid loss and an unknown option;
- epic: an invalid direction, an unknown option, and `-p -` still accepted;
- register: an unknown option in `@@fix`, and a valid nested command line;
- optinorm: `--nope`, `--affine foo`, a bare `--affine` and `--affine -a 1`, and negative numeric values.

Before the fix 23 tests fail; after it all 39 pass. `pytest -k cli` goes from 554 passed to 593 passed (5 skipped), and nothing that passed before fails. The branch merges cleanly with master and with #231.

**New bugs noticed, not fixed (added to #171):**
- A known option placed after a group is still swallowed by a multi-value option in that group: `estatics -c -e a.nii -v` gives `echoes == ['a.nii', '-v']`. Fixing this means stopping value collection at any tag, which changes how values are consumed more broadly.
- An invalid choice in an optional position, or past the minimum count, still falls through to `Don't know what to do with 'foo' at position N`. Examples are `--steps aff foo` and register's optional group names.
