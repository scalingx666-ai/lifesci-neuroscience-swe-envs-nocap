## Summary

Four small fixes in the meanspace / autoreg code paths, one commit each.

- **meanspace help**: the help text in `meanspace/cli.py` (printed by `-h` and on parse errors) described an unrelated `-i fix mov file.lta` interface. It now uses the up-to-date help defined in `meanspace/parser.py`.
- **autoreg `-ls` (`BacktrackingLineSearch`)**:
  - The closure (which calls `backward()`) ran under `torch.no_grad()`, so `-ls` always raised "element 0 of tensors does not require grad". It now runs with autograd enabled, as in `torch.optim.LBFGS`.
  - When no tried step decreased the loss, the parameters were left at an untested (halved) step while the previous step's loss was returned to the LR scheduler. The initial parameters and loss are now restored.
- **`spatial.compute_fov`**: `affines.reshape(...)` / `shapes.reshape(...)` were no-ops (`reshape` is not in-place), so passing a single matrix failed. Batched inputs, as used by meanspace and autoreg, are unaffected.
- **`spatial.rmind`**: the first feature (used to normalize the descriptor) must be the first ring of neighbours, but the distances came from a `set`. It is now sorted explicitly. Results are unchanged on CPython.

## Tests
- New `nitorch/tests/test_line_search.py`: it crashes on master and passes here.
- New `nitorch/tests/test_compute_fov.py`: the single-matrix case fails on master and passes here.
- End-to-end `nitorch autoreg ... -ffd -ls` on a synthetic pair: the loss decreases monotonically (0.054 → 0.011 in 30 iterations, against 0.031 without `-ls`).
- `nitorch meanspace` gives identical output before and after. `rmind` gives identical output for radius 1.5–4, in 2D and 3D.
- `nitorch/tests` (non-gradcheck tests) passes.
