# Issue

**Title:** FIX(compose): use spatial.shoot for shooting velocities, like reslice

## Description

Part of #171. This applies your decision on an item found while investigating `reslice -v2`.

**Bug:** `compose -v`/`-v2`/`-iv`/`-iv2` always exponentiated the velocity as a stationary field (`spatial.exp`) and ignored the shooting JSON. `reslice` does not have this problem.

**Fix:**
- A new shared helper in `nitorch/cli/registration/helpers.py` is used by both reslice and compose:
  - `shoot_keys` and `load_shoot_parameters`, moved out of reslice;
  - `find_shoot_json(fname)`, which returns `<vel>.json` only if it exists and has a `bending` key;
  - `exponentiate_velocity(vel, affine, json=None, square=False, inv=False)`. It halves the velocity for `square`. With a JSON it calls `spatial.shoot(..., displacement=True, return_inverse=inv, voxel_size=<from affine>, **prm)`; without one, it calls `spatial.exp`.
- **reslice:** it now calls the helper, and its behaviour is unchanged. The old names (`_shoot_keys`, `load_shoot_parameters`) are kept as aliases.
- **compose:** `-v`/`-v2`/`-iv`/`-iv2` now take `FILE [JSON]`. A JSON is used if given right after the file, or found next to it as `<vel>.json`.
  - `-v2` halves the velocity before shooting, which gives the geodesic midpoint.
  - `-iv` returns the inverse.
  - The JSON check sits after the transform's option loop, so this merges cleanly with #246 (`--`).

**Docs:** a writer subagent updated `compose.md`:
- the "always exponentiated" sentence is removed;
- the `-v`, `-v2` and `-iv` rows describe the JSON rule;
- an example now mentions the JSON.

**Tests:** the new `nitorch/tests/test_cli_compose_shoot.py` has 12 tests. The velocity has 2 mm voxels, so the voxel size actually matters.
- With an explicit JSON, `-v`, `-v2`, `-iv` and `-iv2` each match a direct `spatial.shoot` call and reslice's `exponentiate_transforms`, and differ from `exp`.
- An auto-detected JSON works the same way.
- An unrelated JSON (with no `bending` key) is ignored.
- A velocity without a JSON still uses `exp`.
- An explicit JSON followed by more options parses correctly.

8 tests fail on master; the 4 SVF cases pass on both. `-k "compose or reslice or shoot"` gives 95 passed and 7 skipped, and `test_cli_*.py` gives 678 passed and 5 skipped.

**Behaviour change:** a velocity written by `register` with its `vel.json` beside it is now shot geodesically by `compose`, as in `reslice`, so its output changes. Stationary velocities are unchanged.

**Noticed, not fixed:** the docstrings of `compose/cli.py` say "vexp" and "nicrop".
