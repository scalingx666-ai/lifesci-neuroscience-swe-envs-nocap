# Issue

**Title:** FIX(core): quantile(mask=, bins=) bin range over in-mask values

## Description

Part of #114

## Summary
- **Bug:** the histogram path of `nitorch.core.utils.quantile(..., mask=, bins=)` computed the bin range (min/max) over all values. Masked-out outliers therefore stretched the range and coarsened the bins, so most in-mask values landed in a few bins.
- **Fix:** with a mask, min/max are now computed over `mask > 0` only. Masked-out values have zero weight and fall outside the range, where `histc` discards them, so they cannot affect the result.
- Negative weights are dropped.
- Behaviour without a mask is unchanged. This follows #124, which fixed the exact (sorting) path.

## Tests

- With ±1e3 outliers in the masked-out voxels, the `bins=` result equals the `bins=` result with those voxels replaced by an in-mask value.
- The result is within 1.5 bin widths of `torch.quantile` on the in-mask values.

- **uniseg check:** a tiny `UniSeg` fit (8x8x8 volume, 2 channels, outliers in the masked-out region of `W`) runs and gives finite, sensible means. `uniseg` is the only caller of this path.
