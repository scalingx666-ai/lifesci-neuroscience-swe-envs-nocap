# Issue

**Title:** FIX(topup): duplicate -m, -bw default, optional -d/--modulation, -k vox, Jacobian axis

## Description

Part of #171. I reproduced all five items before fixing them.

1. **`-m` was registered twice in `fit`**, for `--mask` and for `--modulation`. `--mask` matched first, so `-m` never set the modulation. The docs say "`-m` means `--mask`", so `-m` stays `--mask`, and `--modulation` in `fit` now has the short tag **`-j`** (for Jacobian). `apply` keeps `-m` for `--modulation`, since it has no mask option.
2. **`-bw` defaulted to `None`** and crashed both commands: `vel / None` in `apply`, and `vel *= None` at the end of `fit`. It now defaults to `1`, as the help says, which keeps the field in voxels. The missing `-bw` line is added to the help of `apply`.
3. **`-d/--diffeo` and `--modulation` required a value**, because they combined `nargs=1` with `store_true`. They now take an optional value: on its own, the flag means yes, and `yes`/`no` are still accepted.
4. **`-k ... vox`** divided the kernel by `2**level`, where "level" was the pyramid voxel size in mm. `get_kernel` now receives the full-resolution affine, and a kernel in voxels is rescaled to each level as `p * vx0 / vx_level`, consistent with `mm` and `%`.
5. **The Jacobian in `apply` was computed along the wrong axis.** `main_apply` moves the readout to the last dimension, but then differentiated along `dim=readout`. Both small-deformation branches now use `dim=-1`, the same convention as `tools/registration/topup.py`. The `-d yes` branch was already correct.

**Docs:** a separate writer subagent updated `topup.md`:
- the synopsis and options tables;
- the "Always give `-bw`" warning (removed);
- `-j`;
- the optional flag values;
- `-k vox`;
- the Jacobian taken along the readout axis.

**Tests**
- The new `nitorch/tests/test_cli_topup.py` has 25 tests:
  - parser tests for items 1–4, including a check that no short tag is duplicated;
  - `get_kernel` in voxel units;
  - `fit` and `apply` without `-bw`;
  - Jacobian tests: a cosine displacement along `lr`/`ap`/`is`, with `-p` and `-n`, should give 1 ± the central difference along the readout, and 1 when the displacement varies along another axis.
- Before the fix, 22 fail; only the `is`-readout Jacobian cases pass. After it, all 25 pass, and `pytest -k topup` gives 29 passed.

**Behaviour changes**
- **Unwarped intensities change for any readout other than the last axis**, because modulation is now along the readout axis.
- In `fit`, `-m` means only `--mask`; use `-j`/`--modulation` for the modulation.
- `-bw` is optional and defaults to 1.
- `-k N vox` means N voxels of the input image at every level.
- ⚠️ Because the values are now optional, `-d` or `--modulation` written directly **before** the positional inputs (`fit -d pos.nii neg.nii`) takes `pos.nii` as its value. The docs advise putting such flags after the inputs, or giving an explicit value.

**New issues noticed, not fixed** (added to #171):
- The optional-value flags swallow a following positional argument, as described above.
- If no letter of `-r` matches the image orientation, `get_readout` returns the string unchanged, which raises a `TypeError`.
- `_cli` raises an `IndexError` with no arguments.
- `main_fit` prints a debug line, `print(sd.item())`.
