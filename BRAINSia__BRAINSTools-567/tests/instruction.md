**Title:** COMP: Suppress GCC -fvar-tracking-assignments note on CLP headers

## Summary

- Add `-fno-var-tracking-assignments` to `CMAKE_CXX_FLAGS` when building with GCC, suppressing a noisy compiler note on large SEM-generated CLP headers.
- The flag is conditionally applied only for GCC via `CMAKE_COMPILER_IS_GNUCXX`.
- .

## Context

GCC emits `-fvar-tracking-assignments` notes when variable tracking data exceeds
the compiler's limit. This happens on the large `*CLP.h` headers generated by
SlicerExecutionModel's GenerateCLP tool, which use `#define main ModuleEntryPoint`
to redirect `main()` to a library-callable entry point. The warning is purely
cosmetic — it does not indicate a code defect — but it creates noise in build logs.

The root cause is in SlicerExecutionModel's GenerateCLP, not in BRAINSTools itself.
This fix suppresses the note on the BRAINSTools side since we cannot control the
upstream generated header size.

GCC flag to disable this specific diagnostic. The flag has no effect on code
generation or optimization — it only disables the debug info tracking note.
