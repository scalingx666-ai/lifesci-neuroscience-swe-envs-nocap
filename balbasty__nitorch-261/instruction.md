# Issue

**Title:** FIX(orient): -k requires a value

## Description

Part of #171.

`orient -k/--like FILE` took the next word without checking that one followed:
- `orient a.nii -k` crashed with `ValueError: not enough values to unpack`.
- `orient a.nii -k -l RAS` stored `-l` as the reference file. `RAS` was then left over and failed with the misleading "Value RAS does not seem to belong to a tag".

`-k` now checks for its value with `cli.check_next_isvalue`, the same helper `-l` already uses. Both cases raise "Expected a value for tag -k but found nothing." Leaving `-k` out entirely still means "use the input file", as documented.

The other options don't have this bug: `-a`/`-v`/`-c`/`-o` loop with `next_isvalue`, and `-t` takes an optional value with a documented default.

**Docs:** no change needed. `orient.md` already documents `-k FILE` as taking a value.

**Tests:** three new tests in `nitorch/tests/test_cli_orient_vopt.py`: a bare `-k`, `-k -l RAS`, and the normal `-k ref.nii -l RAS`. `pytest nitorch/tests -k orient`: 17 passed, 2 skipped (before: 14 passed, 2 skipped).
