# Issue

**Title:** FIX(io): streamlines savef/savef_new dispatch to subclass overrides

## Description

Part of #171. This is a , for an issue found while working on it.

**Root cause.** In `nitorch/io/streamlines/mapping.py`, the base class defined `savef` with `savef = save` in the class body. That alias stays bound to the base `save`, which raises `NotImplementedError`. As a result, `TrkStreamlines(...).savef()` never reached `TrkStreamlines.save`. The base `savef_new` also simply raised `NotImplementedError`, so `io.savef(streamlines, 'x.trk')` could not work through the generic dispatcher either.

**Fix**
- `savef` now delegates to `self.save(...)`.
- The base `savef_new` now delegates to `cls.save_new(...)`.

This is the same pattern as #207 used for `MappedAffine`. Streamlines are float data and are never scaled, so `savef` is the same as `save`.

**Tests:** the new `nitorch/tests/test_io_streamlines_savef.py` has 4 tests. They check that `savef`/`savef_new` reach the subclass's overrides, both on a minimal subclass and on `TrkStreamlines`. Before the fix 3 of them fail; after it all 4 pass. The IO tests in `nitorch/io` also pass (31 passed). `test_babel.py` was skipped because it needs `wget`, which is not installed here; this is the same on master.

**Behaviour change:** `.savef()` and `savef_new` on streamlines files now call the format's own writer instead of raising `NotImplementedError`.
