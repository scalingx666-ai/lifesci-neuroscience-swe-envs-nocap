# Issue

**Title:** FIX(denoise_mri): CPU default/fallback, -v 0, per-input output names

## Description

Part of #171. I reproduced all three bugs before fixing them.

1. **Device.** The default was `'cuda'`, with no fallback, so the command failed on a machine without a GPU unless `-cpu` was given.
   - The default is now the CPU.
   - `-gpu [N]` asks for CUDA. When CUDA is unavailable, it warns ("CUDA not available. Switching to CPU.") and runs on the CPU, as `denoise` does.
2. **`-v`** was converted with `bool(str)`, so any value, including `0`, kept printing on. The value is now optional:
   - `-v 0`, `false`, `no` or `off` turns printing off;
   - a bare `-v` or `-v 1` turns it on;
   - printing stays on by default.
3. **Output names.** Every output used to be named `den_<last input>_<c><ext>` and took the header of the last input. Each output is now `den_<its own input name><ext>`, with that input's header, as the docstring says.

**Docs:** a separate writer subagent updated three pages:
- `denoise_mri.md`: the synopsis, `-v`, the output naming and its example, the GPU warning (removed), the device rows, the comparison table and the examples;
- `denoising/index.md` and `conventions.md`: both described `denoise_mri` as defaulting to the GPU, and no longer do.

**Tests**
- The new `nitorch/tests/test_cli_denoise_mri.py` has 4 tests. The heavy functions are monkeypatched, so they run fast. They check:
  - the CPU default;
  - `--gpu` without CUDA warns and falls back;
  - `-v 0` prints nothing;
  - two inputs give `den_T1w.nii.gz` and `den_T2w.nii.gz`.
- All 4 fail before the fix. After it, they pass together with `test_cli_denoise.py` (8 passed).

**Behaviour changes**
- The command runs on the CPU by default.
- Output files are named differently: there is no `_<c>` suffix, and each output takes its own input's name and header.

**New issues noticed, not fixed** (added to #171):
- With `-o`, two inputs that share a base name now write to the same file. The docs mention this.
- `cli()` catches every exception, so the command exits with code 0 even on failure.
