## Summary
This commit was pushed to #127's branch after #127 had been merged, so it never reached master. Cherry-picked unchanged.

- `fit_affine_tpm(..., tolerance=1e-6)` replaces the hard-coded stopping test `mi - mi0 < 1e-4`. `mi` is 𝓛/N, so the fit stops when the gain in 𝓛 is ≤ tolerance·N.
- `align_tpm` takes `tolerance` and passes it down, including through the progressive fit. `uniseg` (the only other caller) gets the new default.

**Why 1e-6.** With 1e-4 the fit stopped after 4–6 Gauss-Newton iterations while further iterations still moved the estimate. "Drift" below is the mean displacement between each fit and a reference fit run until the line search fails (median / max, mm):

| tolerance | translation | rigid | affine | GN iterations, time per fit |
|---|---|---|---|---|
| 1e-4 (old) | 0.009 / 0.21 | 0.144 / 0.65 | 0.205 / 9.1 | ~5, 0.25–0.30 s |
| 1e-5 | 0.004 / 0.18 | 0.058 / 0.39 | 0.089 / 8.3 | ~8, 0.31–0.40 s |
| **1e-6** | 0.001 / 0.06 | 0.006 / 0.39 | 0.029 / 1.4 | ~13, 0.49–0.60 s |
| 1e-7 | 0.000 / 0.06 | 0.001 / 0.10 | 0.005 / 1.4 | ~20, 0.80–0.90 s |

1e-6 removes the early stop for about twice the runtime of 1e-4. The translation and rigid sweeps covered 44–45 of 96 configurations before timing out; the affine sweep is complete. Timings were taken on a loaded machine and are only comparable within a column.

The noisy affine case's 12 mm outlier is a poor local optimum that the fit run to convergence also ends in.
