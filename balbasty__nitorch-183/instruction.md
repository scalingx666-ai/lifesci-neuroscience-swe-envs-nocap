# Issue

**Title:** FIX(smooth, metrics): device options, -m tri, -b rect

## Description

Part of #171. Each bug was reproduced by a new test before it was fixed.

- **`--cpu N` / `--gpu ID` in `smooth` and `metrics`.** Both parsers passed `cli.Conversions.device` without calling it. As a result, `--gpu 1` stored a function object, `--cpu 4` stored the raw string, and `metrics` raised a `ParseError`. Both parsers now call `Conversions.device('gpu')` and `Conversions.device('cpu')`, the same way `epic` and `denoise` do. `smooth --cpu N` now also sets the number of threads, as its help text says.
- **`smooth -m tri`** raised `KeyError`, because the kernels expect the name `triangle`. The name is now mapped.
- **`smooth -b rect`** had no effect: the basis name was passed to code that only tests whether the value is truthy. The CLI now maps `rect` to 0 and `tri` to 1.
- **The CUDA device string** was `'cuda: {id}'`, with a space. It is now `'cuda:{id}'`, built by a small `get_device()` helper that can be tested without a GPU.
- **Docs.**
  - `smooth.md`: removed the "Two options do not currently do what they say" box and the `-m`/`-b` caveats. Documented `--cpu [N]`.
  - `metrics.md`: documented `--cpu [N]`. The SSIM caveats and other still-open caveats are unchanged.
- **Tests.** The new `nitorch/tests/test_cli_smooth.py` has 5 CPU-only tests. All 5 fail before the fix and pass after it.
