# Issue

**Title:** FIX(register): only write the nonlinear Hessian when requested

## Description

## Summary

- `@nonlin --hessian` defaulted to `{dir}{sep}{name}_hessian.nii.gz`, so `nitorch register` **always** wrote the Hessian of the nonlinear field.
- Conversely, `-h` could not be used without a value (`nargs=1`: "Not enough arguments for option hessian"), although the help suggested a default path.

Now `--hessian` behaves like `--resliced`:

| | before | after |
|---|---|---|
| (nothing) | `{name}_hessian.nii.gz` written | not written |
| `-h` | parse error | `{dir}/{name}_hessian.nii.gz` |
| `-h PATH` | `PATH` | `PATH` |
| `-h true` / `-h false` | `.format` on a bool / not written | default path / not written |

The help line is updated accordingly.

## Tests
- New `nitorch/tests/test_register_parser.py` covers the cases above at the parser level.
- End-to-end `nitorch register @loss mse @@fix fix.nii @@mov mov.nii @nonlin svf ...`:
  - master: `svf_hessian.nii.gz` written without `-h`; with `-h`, parse error.
  - this PR: not written without `-h`; written with `-h`.
