# Issue

**Title:** FIX(denoise, relax): honour -x relax from the first iteration; correct relax colouring

## Description

Part of #171. This implements your decisions after the investigation of the forced CG warm-up.

1. **`tools/denoising/tv.py`:** `optim0 = 'cg' if n_iter < 10 else optim` forced CG for the first 9 IRLS iterations. With the CLI default `-n 10`, `-x relax` therefore almost never ran relax.
   - The warm-up is removed, so the requested solver is used from iteration 1, and the docstring says so.
   - In the experiments, CG and relax reached the same solution, and CG throughout was never worse.
2. **`spatial/_solvers.py` `solve_field`:** it called `core.optim.relax` without `dim`, and `relax` expects channel-last tensors while `solve_field` is channel-first. As a result, the red-black checkerboard covered the wrong axes.
   - The relax branch now moves the channel last, wraps `forward`/`precond` so that slicers are converted back, passes `dim`, and moves the result back.
   - The other relax callers in `_solvers.py` already used channel-last tensors, and now pass `dim` too: `_FieldFMG`/`_GridFMG` `make_solvers(_kernel)`, `solve_grid(_kernel)` and `solve_field_kernel`. Without it, they were wrong whenever there were leading batch dimensions.
3. **`core/optim.py` `relax_slicers`, a third bug found on the way:** the parity was computed over `slicer[1:-1]`, which skipped the first spatial axis, so neighbours along one axis got the same colour.
   - Each slicer now starts with an Ellipsis, `(Ellipsis, *spatial, slice(None))`, so the parity covers every spatial axis and leading batch dimensions pass through.
   - Batched `solve_field` relax used to crash; it now runs.

The compiled C backend is not affected: `c_relax` and `c_relax_grid` take `dim` explicitly. It is not available in this environment, and the new tests skip when it is present.

**Docs:** a writer subagent updated the `-x` row in `denoise.md`. The chosen solver is now described as used throughout, with a hint that relaxation may need more inner iterations than CG.

**Tests:** the new `nitorch/tests/test_denoise_relax.py` has 5 tests.
- Relax is used from the first iteration. This spies `solve_field` and expects `['relax']*3`.
- Relax matches CG within 1e-2 relative on a 12³, 2-channel phantom.
- The checkerboard gives different colours to neighbours along X, Y and Z, and the same colour across channels.
- 3D convergence: the relative error after 300 sweeps drops from about 5e-7 to about 5e-8.
- A batched (B, K, X, Y, Z) problem runs; it used to crash.

4 fail before the fix; the relax-versus-CG agreement test passes on both. After the fix:
