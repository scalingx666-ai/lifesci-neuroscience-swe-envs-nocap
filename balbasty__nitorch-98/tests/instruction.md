# Issue

**Title:** FIX(_ts): align TorchScript pull/push/grad with the compiled backend

## Description

## Summary

The TorchScript backend (`nitorch/_C/_ts`, used whenever the C++ extension is not compiled, e.g. a plain `pip install`) disagreed with the compiled backend in two ways.

- **1D, spline order ≥ 2 (wrong values)**: `torch.cartesian_prod` returns a 1D tensor when given a single tensor. It was unsqueezed in the wrong dimension (`unsqueeze(0)` instead of `unsqueeze(-1)`), so all nodes were treated as one N-dimensional node and only one node contributed. For example, cubic interpolation of `[1..5]` at integer coordinate `k` returned `x[k]/6` instead of ≈`x[k]`. This affected pull, push, count and grad (5 places in `nd.py`).
- **`extrapolate=False` tolerance (backend inconsistency)**: points were considered out of bounds as soon as they were 1e-5 voxel outside the field of view. The compiled backend (`TINY` in `pushpull_common.cpp`) and torch-interpol use 5e-2. Results therefore differed between backends for samples within 0.05 voxel outside the edge.

## Tests
- New `nitorch/tests/test_grid_pull_ts.py`: 1D spline reproduction of linear functions, and the edge tolerance in 1D/2D/3D. All 6 tests fail on master and pass here.
- Compared against torch-interpol (which derives from this code): pull/push/grad now match in 1D/2D/3D, for orders 0, 1, 2, 3, 5 and dct2/dft/zero bounds, with and without extrapolation. On master, every 1D order ≥ 2 combination differed, plus some 3D order-5 cases. The only remaining differences are 3 cases where torch-interpol itself returns a `bool` tensor (nearest, 2D, `extrapolate=False`), which is a bug on their side.
- `nitorch/tests/test_gradcheck_spatial.py -k "grid_pull or grid_push or grid_count or grid_grad"` on the TS backend: **1008 passed**.
