# Issue

**Title:** FIX(inpaint): accept >4D inputs, fix convergence test

## Description

Part of #171.

1. **`ensure_4d`** threw away the result of `squeeze()` and always raised, so any input with more than 4 dimensions failed. It now uses the same pattern as #189: drop a size-1 dimension from index 3 up, and raise only when no singleton non-spatial dimension is left.
2. **The convergence test** compared `(ll_x0 - ll_w0)` against `(ll_x + ll_w)`. Because the signs were mixed, it never converged and always ran to `--max-rls`. It now compares the objective that the loop already prints, `ll_x + ll_w` (the TV majorizer), between successive iterations, and stops when `|(ll0 - ll) / ll0| < tol_rls`.
   - On a test volume, the objective goes 728.98 → 622.21 → 622.196, then `Converged`.

**Docs:** `inpaint.md` now says that each file is a 3D volume with an optional 4th channel dimension, and that further dimensions are accepted only if they have size 1. The existing text about `--tol-rls` is now accurate.

**Tests:** the new `nitorch/tests/test_cli_inpaint.py` has 2 tests.
- An 8×8×8×1×1 input with NaN voxels runs, and its output is all finite.
- On a volume with a block of NaN voxels, the iterations are counted from the verbose output. With `tol_rls=1e-2` the loop stops early with `Converged`; with `tol_rls=0` it runs all 30 iterations.
- Before the fix both fail; after it both pass.

**Behaviour changes**
- `--tol-rls` now actually stops the loop. With the default of 1e-5, a run can end before `--max-rls`, so it is faster and the results may differ slightly.
- Files with extra size-1 dimensions are now accepted.
