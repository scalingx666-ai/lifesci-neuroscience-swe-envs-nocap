# Issue

**Title:** FIX(spatial): affine_conv offset accounts for dilation; SpatialLattice.conv argument order

## Description

Part of #171. This is a , for an issue found while working on that PR.

**Bug.** With dilation D > 1, `affine_conv` ignored D in the output-affine offset. The result was shifted by (D−1)(K−1)/2 input voxels, and the transposed branch had the same error.

**Derivation**
- **Forward:** output voxel j reads input voxels i_k = j·S − P_low + D·k, for k = 0…K−1. Their centre is j·S − P_low + D(K−1)/2, so the voxel-to-voxel map has scale S and offset **D(K−1)/2 − P_low**. The code used (K−1)/2 − P_low.
- **Transposed:** this is the inverse map, j = (i + P − D(K−1)/2)/S, so the offset is **(P − D(K−1)/2)/S**.
- The output-shape formulas were already correct.

**Also fixed.** `SpatialLattice.conv` (`spatial/_layout.py`) passed `transposed` positionally into the `dilation` slot. That gave D = 0, so a K=3 conv on a 10×10 lattice returned shape (10,10) instead of (8,8). Its default `stride=None` also crashed. It now passes keyword arguments and uses `stride or 1`.

**Tests:** the new `nitorch/tests/test_affine_conv.py` has 29 tests. Each one maps a known input position through the operation and then through the output affine, and checks that it lands on the same world position.
- `F.conv1d`: a single bright voxel convolved with a centre-tap kernel, with asymmetric padding.
- `F.conv_transpose1d`, with the same setup.
- `spatial.pool(..., affine=)` in 3D, with mean and median, on a coordinate ramp: the mean or median of a ramp over a window is the window centre.
- `SpatialLattice.conv`: shape and affine.
- Cases (K, S, D, (lo, hi)): (3,1,1,(1,1)), (3,2,1,0), (3,1,2,(2,2)), (3,2,2,0), (5,1,3,(1,4)), (3,3,4,(2,0)), (1,2,1,(0,1)), (5,2,2,(3,1)).

Before the fix, 18 fail: every case with D > 1, plus the `SpatialLattice` test. After it, all 29 pass. `pytest -k "conv or pool or affine"` gives 417 passed and 9 skipped.

**Behaviour change:** only Python API calls with dilation > 1 change, that is `spatial.pool(..., dilation>1, affine=...)` and direct `affine_conv` calls. No CLI command exposes dilation. The other callers, `autoreg` and `tools/registration/objects.py`, use D = 1. `SpatialLattice.conv` now returns the correct shape and affine; nothing else in the repository uses it.

**Not changed:** the transposed branch still rejects asymmetric padding, and `SpatialLattice.conv` does not expose `dilation`.
