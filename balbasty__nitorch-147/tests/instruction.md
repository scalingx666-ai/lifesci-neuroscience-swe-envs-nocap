# Issue

**Title:** FIX(spatial): diagonal of the regularisers used by the relax smoother

## Description

## Problem

The relaxation smoother of the multigrid solvers (`nitorch register ... @nonlin svf @@optim gn -q relax`) converged very slowly. The diagonal it used for the bending energy did not match the operator unless the voxel size was 1. That includes every coarse multigrid level, so even voxel size 1 was affected.

`bending_diag` used `6 * sum(1/vx^2)` where the operator needs `6 * sum(1/vx^4)`. The compiled backend (`relax_grid_common.cpp`) already uses the correct value.
- **Isotropic voxels larger than 1:** the diagonal was overestimated, so relaxation was heavily over-damped. With voxel size 4, the true diagonal at an interior voxel is 2.625, but the solver used 19.5.
- **Some anisotropic voxels:** the diagonal was underestimated, so relaxation diverged. With voxel size `[2, 3, 0.5]`, the solver used 38 where the true value is 108.

## Changes

- Fix the unweighted diagonal in `bending_diag`.
- Fix the weighted (RLS) kernels:
  - `membrane_diag` was 2× too large; it now matches the operator and the compiled backend's weighted membrane relaxation.
  - `bending_diag` had a wrong centre and wrong corners.
- Add `regulariser_grid_diag`, the exact diagonal of `regulariser_grid`, covering absolute, membrane, bending, Lame shear and Lame divergence, weighted or not.
  - It is exact in the interior of the field of view, and never below the true diagonal near the edges, so relaxation cannot diverge from it.
  - All four grid solver paths use it instead of their own copies of the formulas.
- Before this change, the weighted grid solvers crashed while building the diagonal.

### Other bugs fixed along the way
- `spconv` gave wrong results for kernels without channel dimensions, and crashed on per-channel kernels.
- `regulariser_kernel` ignored the `absolute`/`membrane`/`bending` values.
- `regulariser_grid` swapped the two Lame constants. The solvers and the C code already used `lame[0]` for shear and `lame[1]` for divergence. ⚠️ This changes the output of `regulariser_grid` whenever the two constants differ.
- `_lincomb` could write into its input when the first weight was 1. This affected weight maps in `membrane_diag`, and the input of `sobel`.
- `_GridFMG` passed weights with a trailing channel dimension to the regularisers, and assumed weight dicts had a `'lame'` key.
- C relax (grid, bending/Lame): the sign of the mixed derivatives of the third component was wrong under sign-flipping boundaries such as `dst*` (copy-paste error). ⚠️ **Not compiled or tested:** the C extension isn't built in the environment used for this PR.

## Tests

New tests in `nitorch/tests/test_grid_solvers.py`:
- Impulse probe on a 9×9×9 grid: the diagonal of `membrane_grid`/`bending_grid` matches `*_diag * vx**2` for voxel sizes `[1,1,1]`, `[4,4,4]`, `[64,64,8]` and `[2,3,0.5]`.
- `regulariser_grid_diag` against a probed diagonal for every term, weighted or not, with `dft` and `dct2`, in 2D and 3D. It must be exact in the interior and never below the true diagonal anywhere.
- `spconv` against a dense circular convolution, for scalar, per-channel and channel-mixing kernels.
- `regulariser_kernel` and `regulariser_grid_kernel` against their operators.
- `solve_grid_fmg(..., optim='relax')` against a converged `solve_grid(..., optim='cg')`: unweighted 3D and 2D, and weighted 2D.
- `solve_field_fmg(..., optim='relax')` against a converged `solve_field(..., optim='cg')`, unweighted and weighted.
- Weight maps are not modified in place.

The impulse and convergence tests fail on `master`.
