# Issue

**Title:** FIX(cli): `-t` tag of chunk, unstack, extract_patches and reorient

## Description

Part of balbasty/nitorch#171.

## Summary
The parsers of `chunk`, `unstack`, `extract_patches` and `reorient` tested `tag in ('t', '--transform')`. Because of the missing dash, `-t` raised "Unknown tag -t", so only the long form worked.

Fixing the tag exposed further bugs in the same code paths, which this PR also fixes:
- `unstack -d N` stored `N` as a string and crashed with `'>' not supported between 'str' and 'int'`.
- `reorient -t` passed the whole list of transform names to each `reorient()` call, which then raised `AttributeError` when it called `.format` on the list. Its default template also used an undefined `{orientation}` placeholder. It now uses `{layout}`, which gives `{base}_2_LPS.lta`, and `layout` is resolved to its name even when `-o` is not used.

## Test plan
`nitorch/tests/test_cli_transform_tag.py` checks that `-t` writes the expected `.lta` files for the four commands, that `unstack -d 0` works, and that `reorient -t NAME` uses the given name. All 6 tests fail on `master` and pass with this PR.

The chunk/unstack affine bookkeeping for 4D inputs and negative `-d` (also in balbasty/nitorch#171) is not addressed here.
