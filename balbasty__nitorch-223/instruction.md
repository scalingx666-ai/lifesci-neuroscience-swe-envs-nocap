# Issue

**Title:** FIX(denoise_mri): disambiguate outputs of inputs sharing a base name

## Description

Part of #171. This is a , for an issue found while working on it.

**Bug (reproduced):** each output was named `file_replace(fname, prefix='den_', dir=dir_out)`, and `-o` is a directory. So `denoise_mri a/t1.nii.gz b/t1.nii.gz -o out` wrote both results to `out/den_t1.nii.gz`, and the second one silently overwrote the first. The same happened without `-o` when one file was given twice.

**Fix:** a new helper, `_output_fnames(fnames, dir_out)`, works out all output names before anything is written. Only outputs that would collide get their 1-based input position before the extension, as in `den_t1.1.nii.gz` and `den_t1.2.nii.gz`. Every other output keeps its plain name.
- *Decision:* raising a `ParseError` was not an option, because `-o` is a directory rather than a single file, so there is no case where the user explicitly asked for one name.
- The `.{i}` suffix keeps every output and does not change any name that already worked. It is the same convention as uniseg's `.{c}` per-channel suffix in #219.

**Docs:** a writer subagent updated the Output section and the `-o` row in `docs/cli/reference/denoising/denoise_mri.md`, with an example. It also updated the `-o` help text and the `dir_out` docstring.

**Tests** (`nitorch/tests/test_cli_denoise_mri.py`):
- an end-to-end run of the CLI with two inputs that share a base name, with the noise estimate monkeypatched and 2 iterations;
- a unit test of the helper, covering mixed colliding and non-colliding names, no `-o`, and the same file given twice.

Both tests fail before the fix. After it, all 10 tests in `test_cli_denoise_mri.py` and `test_cli_denoise.py` pass.

**Not handled (rare):**
- An added index can itself match another input's plain output name. For example, `a/t1.nii`, `b/t1.nii` and `c/t1.1.nii` give two `den_t1.1.nii`.
- `file_replace` takes everything after the first dot as the extension, so `sub.01_T1w.nii` gets the index in the middle. This was already the case before this PR.
