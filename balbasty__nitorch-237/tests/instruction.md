# Issue

**Title:** FIX(autoreg, crop): named errors for garbled values; bool words; -o/-r counts

## Description

Part of #171. These are leftovers from #230 and #231, all in the "Still open" list. Each was reproduced first.

1. **Garbled values raised a raw `ValueError`.** Variable-length loops called bare `float()`/`int()`. This affected:
   - crop `-s`/`-c`;
   - autoreg `-p`, `-w`, `-l`, `-g`, the regularisation factors, the leading factor of loss and transform groups, and the `-pyr` levels.

   A new `nitorch.core.cli.convert_value(value, opt, convert, name=None)` raises a `ParseError` that names the option, and `pop_values` now uses it, with the same messages as before. In autoreg, `pop_all`, `pop_factor` and `pop_bool` wrap the helpers, and `-pyr` rejects ranges with more than three parts. Examples:
   - `-w/--weights expects <float>, got 'abc'`
   - `-s/--size expects <float> or vox|ras, got 'abc'`
   - `-rig expects <factor: float>, got 'abc'`
   - `-pyr/--pyramid expects <int> or [start]:stop[:step], got '1:x'`
2. **Bool words.** autoreg `-exc`/`-z`/`-sd`/`-prg` used `bool(int(x))` behind case-sensitive first-letter checks. Words like `False` or `no` crashed, and `tomato` was read as `True`.
   - A new `Conversions.strict_bool` accepts t/true/y/yes/f/false/n/no in any case, or an integer, and raises otherwise. `Conversions.bool` returns its input unchanged on failure, so it could not be used.
   - A bare flag still means true.
3. **`-o`/`-r` count in `-fix`/`-mov` blocks.** Outputs were zipped with the files, so with fewer outputs than files, the extra files were silently not written. `check_output_count` now applies these rules:
   - one value per file is unchanged;
   - a single `true`/`false` or a `{base}`/`{dir}` template is applied to every file;
   - a single plain path for several files raises `-o: a single path for N input files would overwrite itself; use a template such as {base}.moved{ext}, one value per file, or true/false`. A template that uses only `{ext}` counts as a plain path, because `{ext}` rarely differs between files;
   - any other count raises `-o expects 1 value per input file (N), or a single template; got K`.
4. **`-pyr` inside transform groups** was already parsed as levels on master; the old `float(opt.stop)` code was removed by #231. A regression test now covers it.
5. **autoreg's `check_next_isvalue`**, unused since #231, is removed.

**Docs:** a writer subagent updated `autoreg.md`:
- the Outputs section and the `-o` row give the count and template rules, quoting both errors;
- a new "Boolean options" subsection, linked from the `-exc`/`-z`/`-sd`/`-prg` rows, lists the accepted words and the error, and notes that numeric errors name the option.

`crop.md` has no section on errors, so it was not changed.

**Tests:** 30 new tests in `test_cli_autoreg.py` and the crop tests:
- 12 garbled autoreg values and 4 garbled crop values;
- bool words and a bad bool;
- the output count rules, a single template, and a single plain path rejected for both `-o` and `-r`;
- `-pyr` in a transform group, and the removed helper.

The new tests fail before the fix; the grammar and `-pyr` tests pass both before and after. `pytest -k cli` gives 763 passed and 5 skipped.

**Behaviour changes**
- Words other than true/false/yes/no and integers are now errors for the bool options.
- A single plain output path for several files is now an error. Before, only the first file was written.

**New bugs noticed, not fixed (added to #171):**
- autoreg `-pad PAD [UNIT]` takes any value after the number as the unit, without validating it.
- `-mi -n` accepts only the exact string `inf`.
