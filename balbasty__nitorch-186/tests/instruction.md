# Issue

**Title:** FIX(crop): -k alone, -b bounding box, -t output transform

## Description

Part of #171. All three bugs had been confirmed by running the command, and each now has a test.

1. **`-k` alone** failed with "At least one of size/like/transform must be provided", because the size taken from the reference was never marked as given. It now crops to the reference's shape and position.
2. **`-b`** crashed because `dat.numpy()` was called on an ndarray. The mask now comes from `fdata()`, and the slice is taken from the mapped file.
   - **Off-by-one:** the centre was `(max+1+min)/2`. It is now `(max+min)/2`, so the first voxel kept is exactly `min`.
   - **Test:** the crop of a blob at `[3:7, 5:9, 1:4]` is checked exactly, along with the shift of the affine.
3. **`-t`** is now read as an *input* only when none of `-s`, `-k` or `-b` is given. Otherwise it is an *output*: `-s 4 6 2 -t crop.lta` writes the file, and a bare `-t` writes `{base}.crop.lta`. Writing the file and then reading it back gives the same crop.

**Docs**
- `crop.md`: removed the `-k`/`-b` limitations warning, and rewrote the note on when `-t` is an input or an output. Updated the `-k` example and added a `-b -t` example.
- `preparing.md`: replaced the "stay with `-s`/`-c`" warning with a tip that points to the reference.

**Tests**
- The new `nitorch/tests/test_cli_crop.py` has 8 CPU-only tests. All 8 fail before the fix and pass after it.

**Behaviour changes / choices to confirm**
- `-s … -t FILE` now writes FILE, where it used to try to read it. Reading never made sense in that case, because the explicit size overrode the one in the file.
- On axes where the old rounding was wrong, `-b` boxes now start one voxel earlier.
- **Design choice:** the old built-in help said "`-t` is an input if none of s/c/l/k", which counts `-c`. The reference docs said "none of -s, -k or -b", and this PR follows the docs, so `-c -t FILE` still reads FILE and `-c` overrides its centre. Changing this is one line if you prefer the other rule.

**Still open (not changed here)**
- The rule that only one of `-s`/`-k`/`-b` may be given is still not enforced.
- `-k` with a reference stored in a different layout is untested.
