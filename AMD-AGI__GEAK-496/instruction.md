# Issue

**Title:** feat(tools): add ONNX Runtime EP kernels as a GEAK optimization target

## Description

## Summary

- Adds a reusable framework for GEAK to **optimize ONNX Runtime Execution-Provider kernels** (HIP EP, client RDNA3.5 gfx1151 first, DC GPU later) via `mode=optimize`, with **zero JS workflow changes** — a task is pure data (`config.yaml` + `task_meta.json` + a runner), auto-discovered and frozen into the COMMANDMENT.
- Introduces an **op registry** (`tools/ep_op_registry.yaml`) + **task generator** (`tools/gen_ep_task.py`) + **data-driven runner** (`tools/ep_task_runner.py`) supporting three oracles: `fast` (standalone hipcc harness), `numeric` (ONNX-vs-CPU pytest), and a new self-contained `selfcheck` (in-harness CPU reference + GPU/CPU timing, no ORT/NumPy).
- Adds the `layernorm` selfcheck template (`tools/selfcheck_templates/layernorm`) — editable `kernel_src/` + frozen harness + frozen ABI header — from which `gen_ep_task.py --op layernorm_selfcheck` generates a task on demand (no example task dir is checked in). Proven end-to-end on gfx1151 (compile/correctness/performance PASS, ~20–24× over the CPU reference). It is a standalone HIP microbenchmark and does not validate EP integration.

- [x] Numeric `compile` on gfx1151 against both ROCm/hip-ep main (`3c569cac`, built from source) and hip-ep-2bit-fpzp, with `--ep-build-cmd "cmake --build <build> --target custom_kernels_gfx1151"`: only `layer_norm_kernel.hip` is rebuilt, `build/ep/` holds the EP's libraries plus the rebuilt `libcustom_kernels_gfx1151.so`, the `#error` probe fails compile, and the EP tree is restored after every run.
- [x] Numeric correctness/performance PASS on gfx1151 against ROCm/hip-ep main (`3c569cac`) plus ROCm/hip-ep#1350: a task generated by `gen_ep_task.py --op layer_norm` runs compile/correctness/performance with 42/42 cases passing and 42 timings parsed, and the `#error` probe still fails compile. Without ROCm/hip-ep#1350 the EP's LLVM JIT aborts at init on Linux (`relocation ... __dso_handle ... out of range of Delta32 fixup`) for every case, and the runner correctly exits 1. The registry's `layer_norm` selector now excludes the `TestGroupNorm` cases that share `test_layer_norm.py`: they test a different kernel, and ORT's CPU EP has no `com.microsoft.GroupNorm` reference, so they can never pass.
- [x] Generator round-trip: `gen_ep_task.py --op layernorm_selfcheck` reproduces a functionally-identical task (kernel/harness/header/config/runner byte-identical).
- [x] `tools/` is outside the coverage denominator in `pyproject.toml`, so the new tests are additive and don't move the `fail_under` gate.
