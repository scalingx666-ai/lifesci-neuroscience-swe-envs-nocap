# Issue

**Title:** FIX(autoreg): true/false and template checks for output options

## Description

Part of #171. This is a  and #228, for an issue found while working on #228.

**Bug (reproduced):** autoreg stored its output option values as raw paths. As a result:
- `-o false` on a transform group (`-rig`, `-aff`, `-dif`, `-ffd`, …) wrote a transform file named `false`, and `true` was taken as a file name too;
- `-all -o` required a value and treated it as a path;
- `-o`/`-r` in `-fix`/`-mov` (the updated and resliced images) always collected file names, so `-o false` wrote an image named `false`;
- template keys were never checked, so a typo only failed later with a `KeyError`.

**Fix**
- **`parser.py`:** three new local helpers. autoreg has its own parser, so they live there.
  - `bool_or_path`: `true`/`yes`/`1` (or no value where allowed) give the default path, `false`/`no`/`0` mean nothing is written, and any other value is a path or template.
  - `check_template`: rejects unknown keys at parse time with `[ERROR] Invalid path template ...` and exit status 1. Image templates accept `{dir}`, `{base}` and `{ext}`; transform templates accept `{name}` and `{ext}`.
  - `parse_image_output`: handles `-o`/`-r` in file groups.

  `-all -o` with no value or with `true` keeps the default `{name}{ext}`, and `-all -o false` turns transform output off.
- **`struct.py`:** with several input files, each entry can be `true`, `false` (that file is skipped) or a path.
- **`main.py`:** `write_transforms` skips a transform whose output is `False`, and the image writers skip disabled entries.

**Docs:** a writer subagent updated `autoreg.md` and the help string.
- The option tables show `[OUT]`.
- The Outputs section now covers the switches, the template keys, the one-value-per-file rule with an example, and the template error.
- `-r` is removed from the `-all` options, because `-all` never parsed it.

**Tests** (`nitorch/tests/test_cli_autoreg.py`):
- three parser tests: transform switches, image switches, and template validation;
- one tiny run with `-o false` on both the image and the transform and `-r true`, which checks that the only new file is `mov.resliced.nii`.

These 4 tests fail before the fix. After it, all 23 tests in the file pass.

**Behaviour changes**
- `0`/`1`/`true`/`false`/`yes`/`no` are now switches on these options, so they can no longer be used as literal file names.
- A bad template key fails before the fit.
- `-all -o` no longer requires a value.

**New bugs noticed, not fixed (added to #171):**
- A file group given fewer `-o`/`-r` values than it has input files silently skips the extra files.
- `parse_transform` handles `-pyr` with `opt.stop = float(opt.stop)` instead of parsing the pyramid levels, so `-pyr` inside a transform group looks broken.
- With every output set to `false`, `write_data` still computes the inverse field. This only affects performance.
- The `-all` help lists `-init`, which the code does not accept there; the docs already say so.
