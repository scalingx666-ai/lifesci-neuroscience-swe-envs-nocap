# Issue

**Title:** FIX(chunk, unstack): orientation matrix for 4D inputs and negative -d

## Description

Part of #171. This bug had been confirmed by running the commands.

The affine bookkeeping indexed a 3-element spatial slicer with `dim`. So with 4D inputs or a negative `-d`, the orientation matrix was shifted along the wrong axis, and `-d 3` raised an `IndexError`. The fix is the same in `chunk/main.py` and `unstack/main.py`:
- `dim` is converted against the full data ndim before use.
- The test for a non-spatial axis is now `dim >= ndim` (it was `>`).
- In that case the input affine is kept for **every piece**. The list of unchanged affines was sized with `len(dat)`, the length of the first data axis, instead of the number of pieces.

**Behaviour changes**
- On a 4D volume with the default `-d` or `-d -1`, every piece now keeps the input affine. Before, it was shifted along the third spatial axis.
- `-d 3` on a 4D volume now works instead of raising.
- `-d -2` on a 4D volume now shifts along spatial axis 2. Before, it shifted along axis 1.
- 3D inputs and `-d` of 0, 1 or 2 behave as before.

**Docs**
- `chunk.md` and `unstack.md`: removed the two orientation warning boxes.
- Both pages now say that a non-spatial axis keeps the input affine.
- `chunk.md` also explains how a negative `DIM` is resolved.

**Tests**
- The new `nitorch/tests/test_cli_chunk_unstack.py` has 18 tests on a rotated, anisotropic, translated affine. They cover 3D with `-d` 0, 1, 2 and -1, and 4D with the default `-d`, 3, -2, -1 and 0.
- Each test checks the data of every piece and checks that voxel (0,0,0) of each piece maps to the matching world position in the original.
- Before the fix, 8 fail and 10 pass. After it, all 18 pass.
