# Issue

**Title:** FIX(core): quantile(mask=) must ignore masked-out values

## Description

## Summary
`nitorch.core.utils.quantile(..., mask=)` returned wrong quantiles in its exact (sorting, `bins=None`) path.
- **Cause:** it built a weighted CDF over all sorted values and forced the last entry to 1. As a result:
  - masked-out values leaked into q=1 and nearby quantiles;
  - q=0 returned NaN when the smallest values were masked out.
- **Fix:** masked-out values are now sorted to the end (+inf) and never sampled. Quantiles are linearly interpolated over the in-mask values only, which matches `torch.quantile(input[mask > 0], q)`.
- **Unchanged:** batch, `dim` and `keepdim` handling; the unmasked path; the histogram path (`bins=`).
- A row with no in-mask voxel gives NaN.
- **Behaviour change:** in exact mode the mask is now treated as binary (`mask > 0`). Before, non-binary values acted as (buggy) weights. With `bins=`, the mask is still used as histogram weights. The docstring now documents `mask`.

### Callers
- **Affected** (exact path with a mask):
  - `tools/registration/affine_tpm.py::discretize`: its (0.0005, 0.9995) intensity range could include masked-out values.
  - `tools/registration/losses/utils_gmm2.py::init_gmm2`: GMM initialisation could produce NaN. #122 already bypasses this with a local `_masked_quantile` helper, which is kept as is. It can later switch back to the fixed core function.
- **Not affected:**
  - `tools/registration/pairwise_impl.py` (`--rescale`, `rescale2d`): it indexes `x[~mask]` itself and passes no mask.
  - `tools/uniseg/_fit.py`: it uses the histogram path (`bins=256`), which this PR does not change.

## Tests
New file `nitorch/tests/test_quantile_mask.py` with 6 tests: all fail on master and pass with this fix (about 5 s).
- Results are compared with `torch.quantile` on the in-mask values for q in {0, 0.005, 0.25, 0.5, 0.77, 1}.
- The masks exclude the min values, the max values, both, or a random subset, and the masked-out voxels hold ±1000 outliers.
- Also covered: reducing over non-trailing `dim` with `keepdim=True`, and an all-ones mask giving the same result as no mask.

## Found, not fixed here
- In the histogram path (`bins=`), the bin range (min/max) is still computed over all values, masked-out ones included. Outliers outside the mask therefore coarsen the bins, and `uniseg` uses this path.
