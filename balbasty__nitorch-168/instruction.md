# Issue

**Title:** lcc: share the mask normaliser and use conv1d for long local-mean kernels

## Description

## Summary
This is the LCC item of #158. At 192³, one LCC loss+grad+hess evaluation took 15–16 s, 99% of it in 54 `mkldnn_convolution` calls with a 59-tap Gaussian kernel (FWHM 10% of the field of view). It now takes about 3.4 s, with **lower** peak memory, and nothing is converted to another dtype.

Two commits:

1. **Compute the masked normaliser once per call.**
   - `lcc` makes 9 local means per evaluation (6 forward, 3 backward), and each one re-convolved the mask for its normaliser `conv(mask)`: half the convolutions were redundant.
   - `local_mean(..., norm=)` now accepts a precomputed normaliser, and the new `local_mean_norm(mask, ...)` computes it, for both Gaussian and square kernels. Results are bitwise identical.
   - `lcc` used to replace `mask=None` with an all-ones mask, which disabled the cached `conv(ones)`. It now keeps `None`: same value, gradient and Hessian as with an all-ones mask.
2. **Long separable kernels use `conv1d` along their axis.**
   - The CPU backend (oneDNN) is slow at N-D convolutions with `(K, 1, 1)` kernels, up to 530 ms for one 59-tap pass along the last axis at 192³.
   - The new `conv_axis` treats the input as a batch of 1D rows along the kernel's axis. It is the same operation: bitwise equal in float64, and equal up to rounding (≤ 7e-6 relative on the LCC outputs) in float32.
   - It is used for kernels of at least 15 taps when the stride is 1 on the other axes. Short kernels keep the N-D convolution, which is faster for them.

Everything `local_mean` calls stays TorchScript-compatible: `utils_gmm2.Fwd` is scripted and calls `local_mean`, so LGMMH uses these paths too.

## Effect
192³, 4-thread CPU, master → this PR:

| | no mask | binary mask |
|---|---|---|
| LCC loss | 10.9 s → 2.1 s | 10.4 s → 2.5 s |
| LCC loss+grad | 16.0 s → 2.9 s | 15.0 s → 3.3 s |
| LCC loss+grad+hess | 16.4 s → 3.3 s | 15.5 s → 3.5 s |

The peak memory increase during loss+grad+hess (binary mask) goes from +824 MB to +519 MB.

Outputs compared with master on 2D and 3D, float32 and float64, no mask / binary / soft masks, Gaussian and square kernels, and strides 1 and 2:
- direct N-D convolution and square-patch paths: bitwise identical;
- `conv1d` path: bitwise identical in float64, and at most 6.6e-6 relative (value, gradient, Hessian) in float32.

## Not done: FFT
#158 planned an FFT path for long kernels. I implemented it (it was 9× faster than the old path on CPU), then dropped it, because in single precision its rounding error is *absolute*, about eps × max.
- The local means then return noise (sometimes negative) wherever the exact result is 0, for example far from the mask, where they divide by `conv(mask)`.
- LCC would give every voxel whose window contains no mask a weight of about ±1e-3, instead of 0.
- A float32 LGMMH test (`test_gmm_float32_more_classes_than_tissues`) produced NaN.

Double precision fixes this but increases memory, so the direct convolution stays.

`torch.backends.cudnn.benchmark`, which `nitorch register` turns on, only applies to cuDNN on CUDA. CPU convolutions are never switched to FFT.

## GPU
This PR does not batch moments or channels, so the per-moment structure from 06c927c is kept. `conv_axis` reshapes a volume into a `(rows, 1, L)` batch for `conv1d`, a different cuDNN call. It has not been run on a GPU in this session, so please check it there (cuDNN, and memory) before merging.

## Tests
