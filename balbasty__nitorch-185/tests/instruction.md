# Issue

**Title:** FIX(pad): -s ras, default names, -b dct, pairs in one word

## Description

Part of #171.

- **`-s ... ras`** crashed, because `.tolist()` was called twice. The bug was also worse than that: the code indexed the flattened (lower, upper) vector, which has 2×dim entries, with a permutation that has only dim entries. So it would have padded the wrong amounts even without the crash.
  - Sizes are now read as dim pairs in RAS order (x, y, z), where "lower" and "upper" mean towards the − and + world direction.
  - Each pair is mapped to the stored axis that points along it, and lower/upper are swapped on flipped axes.
  - Each amount is divided by the voxel size and rounded up.
- **Default names.** The output was already `.pad`, but the help said `.crop`. A bare `-t` wrote `.crop.lta`; it now writes **`.pad.lta`**. The `Structure` docstring is fixed too.
- **`-b dct`.** The parser accepted it, but `bounds.to_nitorch` does not know it, so padding failed. The new `parse_bound` maps `dct` to `dct2` and accepts every name and alias that `bounds.to_nitorch` knows. An unknown name now gives a `ParseError`.
- **A pair written as one word**, such as `'(0,16)'`, swallowed the following words and silently dropped them. Pairs are now parsed whether given as one word or several. Malformed or unclosed pairs give a `ParseError`.
- **Docs (`pad.md`).**
  - Removed the caveats about pairs, `ras` and `dct`.
  - Documented the bound aliases and the `.pad.lta` default.
  - Kept the caveat about negative amounts with a constant fill, which is still open.
- **Tests.** The new `nitorch/tests/test_cli_pad.py` has 19 CPU-only tests, including `ras` on a permuted, flipped, anisotropic volume that checks both the shape and that the world position is preserved. Before the fix 13 fail and 6 pass; after it all 19 pass.

**Behaviour changes**
- Scripts that expect `.crop.lta` from `pad -t` need to expect `.pad.lta` instead.
- Malformed `-s`/`-b` values now give a `ParseError` instead of a Python exception or a silent drop.
