# Issue

**Title:** Guard degenerate histogram ranges (constant image / slice)

## Description

Part of #114

## Summary
- New `_guard_range(min, max)` in `nitorch/core/_hist.py`: when `max - min <= 4*eps*max(|min|,|max|,1)` (checked per batch element and per channel), the range is widened symmetrically around its center `c` by `max(|c|,1)/2`. All the mass then falls at the center of the histogram, and the gradient and Hessian (scaled by `bins/(max-min)`) stay finite. It runs in `forward`/`backward`/`backward2`/`backward_hess` of `JointHistCount` and `HistCount`, and in the legacy `_intensity_to_bin`. It covers data-driven and user-supplied limits alike. Non-degenerate ranges are untouched, so results are bitwise identical.
- The index formula is unchanged: `bins/(1 - max/min)` evaluates to `-0` when `min == 0` (and `max > 0`), so it is safe. The only case that breaks it, max == min, is now guarded.
- Also fixed these existing bugs on the same paths:
  - batched `JointHistCount.backward` scaled with `min`/`max` after they had been reshaped, so the shapes didn't match;
  - `HistCount.forward` called `h.reshape(h, ...)`;
  - the legacy histc backward added a spurious offset to the gradient.
