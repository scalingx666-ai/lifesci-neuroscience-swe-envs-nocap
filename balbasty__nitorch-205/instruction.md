# Issue

**Title:** FIX(autoreg): required transform, -init, -all -stop, -dice -w, integer labels, -prg false

## Description

Part of #171. I reproduced all six items before fixing them. Fixing them also uncovered two blocking bugs, `-mi` and `-dice`, which are fixed here as well.

1. **No default transformation.** The command now raises `ParseError: No transformation specified. Use at least one of -tr, -rig, -sim, -aff, -ffd or -dif.` *Decision:* error out rather than invent a default, because the docs say there is none and the help marks `<*TRF>` as required. `-h` still works on its own. The help examples that had no transformation now use `-rig`.
2. **`-init`**
   - **Linear:** the init file is read as a fixed matrix A0, and the optimised transform is applied on top of it, A = expm(q)·A0 plus the centre shift. A new helper, `linear_matrix()`, is used both for the fit and for the outputs. With `-nit 0`, the output equals the init.
   - **Nonlinear:** the old code checked `len(dat)` instead of the channel count, used `trf.shape`/`affine` before they were set, and called a non-existent `.loadf`. The field now keeps its own orientation and is downsampled to the coarsest pyramid level.
3. **`-all -stop`** dropped the next two arguments because of a stray `args = args[2:]`. That line is removed.
4. **`-dice -w`** kept only the first weight, because the append was inside an `if`. All weights are kept now.
5. **Integer label images** failed in several places:
   - labels are no longer rescaled, which failed on int32;
   - `split()` builds proper one-hot maps for both images;
   - the channel count summed channel indices instead of counting them.
6. **`-prg false` with several pyramid levels never terminated.** *Decision:* all parameters are now freed at the first stage, and each later stage moves the nonlinear field to the next finer level. The run therefore terminates, with one stage per nonlinear level.

**Fixed along the way, because the help example and `-dice` could not work otherwise**
- `-mi`: `MutualInfoLoss` (`nn/losses/intensity.py`) called the in-place `clamp_min_` on a view, which raises under autograd. It now uses the out-of-place `clamp_min`.
- `-dice`: `nn.DiceLoss` does not accept `one_hot_map`, so every call raised a `TypeError`. The soft Dice is now computed in `struct.DiceLoss`, one channel per label. The weights can be equal, proportional to label size, or a list.

**Docs:** a separate writer subagent updated `autoreg.md`:
- the required transformation;

**Tests:** the new `nitorch/tests/test_cli_autoreg.py` has 12 tests.
- Parser tests cover items 1, 3 and 4.
- Smoke runs cover items 2, 5 and 6, plus the help example. They use 12³ images, at most 2 levels and 2 iterations, under a 120 s `signal.alarm` guard, so a regression on item 6 cannot hang CI.
- Before the fix, 9 fail, and the `-prg false` test is stopped by the guard. After it, all 12 pass in 7 s.
- `pytest -k autoreg`: 13 passed.

**Behaviour changes**
- A command with no transformation now errors; before, it just copied the images.
- `-init` composes with the estimated linear transformation.
- `-dice` now works with both probability maps and integer labels.
- `-mi` now works.

**New issues noticed, not fixed** (added to #171):
- `autoreg(argv=[])` falls back to `sys.argv`.
- With the default verbosity, the start-up summary crashes on `-oth` groups. This is already documented: use `-v 0`.
- `-g` (FFD grid size) is still ignored.
- The generic `except` handler is commented out.
- `ReduceLROnPlateau` receives a loss that still requires grad, which raises a UserWarning.
