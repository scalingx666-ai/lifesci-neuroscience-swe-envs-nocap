# Issue

**Title:** FIX(register): Powell, OGM and rotation-only affine crashes

## Description

## Summary

Three documented `nitorch register` options crashed. The first one also broke `nitorch affreg` with its default settings.

- **`@@optim powell`**, which affreg uses by default with its default NMI loss. Two crashes, one after the other:
  1. `TypeError: Powell.__init__() got an unexpected keyword argument 'name'`. `make_affine_optim` passes every CLI option through (`name`, `fmg`, ...), but `Powell` did not take `**kwargs` the way the other optimisers do. It now accepts them and passes them on.
  2. `TypeError: object of type 'Parameters' has no len()`. `register` passes an `AffineModel.Parameters` wrapper, not a tensor. That wrapper has no `len`, `clone` or tensor arithmetic. `Powell.step` now adds up its step in a local tensor `dx`, evaluates `x.add(dx + a*d)` and applies `x.add_(dx)` once at the end. For a plain tensor the maths is the same as before. `AffineModel.Parameters.__len__` returns the number of *optimised* parameters, so Powell also works with `-g/--progressive` (checked by hand with `@affine affine -g @@optim powell`). The first loss is now evaluated only if the caller did not pass one.
- **`@@optim ogm`**: `TypeError: OGM.__init__() got multiple values for argument 'momentum'`. The learning rate passed positionally was being taken as `momentum`. `OGM` now takes `*args` like `Nesterov` does. `@nonlin @@optim ogm` goes through the same constructor, so it gets the same fix.
- **`@affine rotation`**: `RuntimeError: The size of tensor a (3) must match the size of tensor b (0)`. `LogAffine._optim_grad` took the rotation gradient from slice `[D:D+D2]`. In a rotation-only basis the rotations are the first parameters, so that slice was empty. It now returns the full gradient in that case. `LogAffine2d` reuses this method.

The diff is small: about 30 lines across `optim/powell.py`, `optim/accelerated.py` and `objects.py`.

## Tests

New file `nitorch/tests/test_register_optim.py`. It builds an analytic smooth phantom, so the moving image is computed exactly with no interpolation, with a known world transform. It runs registration through the real CLI entry points and compares the written `.lta` with `T^-1`. For reference, identity would be off by 0.08 on the linear part and 1.5 mm on the shift.

- `test_affreg_default`: `nitorch affreg` with its default NMI loss + Powell. Uses `-p 1` (one 2 mm level) to keep Powell fast. With the full default pyramid it reaches errors below 0.003 / 0.007, but takes about 2 min on the TS backend.
- `test_register_affine_powell` (single level), `test_register_affine_ogm` and `test_register_affine_rotation`: mse loss, with the rigid / rotation-only transform recovered.
- Unit tests: rotation-basis gradient shape; Powell on `AffineModel.Parameters` with and without a parameter subset; `OGM` built from the CLI options.

## Found, not fixed here

- Powell is slow: about 1 min for a 24³ pair over 3 pyramid levels with the TS backend. Its Brent line search always uses `tol=1e-9`, because `-t/--tolerance` only goes to the outer iterator. Also, the CLI's default `lr=1` means the first trial step is 1 rad of rotation (Powell's own default is 0.02). This needs tuning, not a crash fix.
- `@@optim ogm -x/--relax` and `-r/--restart`, and `nes -r/--restart`, are parsed but silently ignored: the constructors expect `relaxation` / `auto_restart`. The `-o/--output` option is not used either. This belongs to the "ignored options" group.
- `@nonlin @@optim powell` builds a dense `eye(len(x))` over the first dimension of the field, so it is not usable in practice.
- With verbose output, Powell's iteration lines are printed without newlines (cosmetic).
- `LogAffine._switch_basis` has a suspicious condition when the target basis is rigid: `len(src_dat) >= dim + nb_prm`. This path is not reached by the current progressive order.
