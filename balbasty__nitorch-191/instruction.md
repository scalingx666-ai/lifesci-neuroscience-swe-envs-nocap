# Issue

**Title:** FIX(affreg): --no-pyramid, -o false, register arguments

## Description

Part of #171. `affreg` stays affine-only.

1. **`--no-pyramid`** stored `False`, and the code then looped over it, which raised `TypeError: 'bool' object is not iterable`. It now gives `@pyramid --levels 0`, a single level at full resolution. This is the same handling as in #182.
2. **`-o false`** was ignored, so `register` always wrote the `.lta`. `affreg` now passes `@affine -o ''`; `register`'s parser accepts an empty path and then skips writing the transform. `-o true` falls back to the default path.
3. **`max_iter`, `tolerance` and `--line-search`** were passed to `register` as numbers. They are now passed as strings.

The `except Exception` handler in `cli.py` is left commented out. The related front-ends (`register`, `simplereg`, `affopt`, `meanspace`, `vopt`) also leave theirs commented out.

**Docs (`affreg.md`)**
- `-o` now accepts `false`.
- `--no-pyramid` is described as "same as `-p 0`" instead of "raises TypeError".

- Three capture the `register` arguments and re-parse them with `register`'s parser. They check that every argument is a string, the pyramid levels, and the output path.
- Two are short real runs on 12³ images:
  - `--no-pyramid -o false` writes no `.lta`;
  - `-p 0` writes `rigid.lta`.
- Before the fix 4 fail and 1 passes; after it all 5 pass in about 3 s.
