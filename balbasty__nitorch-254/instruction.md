## Description

Part of #171. These three fixes are the ones you chose after the `--` work.

1. **`-pad PAD [UNIT]`** kept any word after the number as the unit. `spatial.compute_fov` reads every unit other than `%`/`pct`/`vox`/`voxel`/`voxels` as millimetres, so `-pad 5 cm` silently meant 5 mm.
   - The unit must now be `%`/`pct`, `vox`/`voxel`/`voxels` or `mm`, in any case. It is stored in canonical form, because `compute_fov` compares the exact string.
   - Any other value raises `-pad/--padding expects <unit: %|pct|vox|voxel|voxels|mm>, got 'cm'`.
   - The unit stays optional. autoreg has no top-level positionals, and arguments after `--` are split off first, so nothing valid can be taken as the unit by mistake.
2. **`-mi -n`** (the histogram spline order) accepted only the exact string `inf`. It now accepts an integer, or anything `float()` reads as +∞ (`inf`, `Inf`, `INF`, `infinity`, `+inf`), which becomes `'inf'` for `MutualInfoLoss`. `-inf`, `nan`, `1.5` and `abc` raise `-n/--order expects <int> or 'inf', got …`.
3. **Unused inverse field.** With several files, each skipped file becomes `None`, so `-o false false` gave `[None, None]`, which counts as true.
   - As a result, `need_inv` was true and the inverse was computed: `spatial.exp(inverse=True)` for `-dif`, `grid_inv` for `-ffd`. The same list also triggered the four `updated`/`resliced` checks, so `update`/`reslice` ran with nothing to write.
   - A `_writes()` helper, true for a list only when some entry is set, now drives all five checks. When anything is written, the outputs are unchanged.
