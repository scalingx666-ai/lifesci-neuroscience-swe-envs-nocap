# Issue

**Title:** FIX(nn.Resize): every forward call crashed; output shape now matches spatial.resize

## Description

Part of #171.

## Cause
`Resize.__init__` stores the `shape` argument as `self.output_shape`, but `Resize.shape()` fell back to `self.shape`, which is the bound method itself. The bug was wider than #171 says:
- **Every forward call crashed**, not only factor-only ones: `forward` always calls `self.shape(image, output_shape=None)`, so the method object became the output shape. Factor-only, shape-only and factor+shape all failed, for all four anchors, in 2D and 3D.
- **`str(Resize(shape=...))` recursed forever**, because `__str__` formatted `self.shape`.

A second bug showed up once the crash was fixed: `shape()` computed the output size as `int(N*f)` for every anchor, but `spatial.resize` uses `floor((N−1)·f)+1` for anchors `f`/`l` (since #249). For example, 8 voxels with factor 2 and anchor `f` gave 16 instead of 15. Because `forward` passes this shape on explicitly, the module returned the wrong shape.

## Fix
`nitorch/nn/modules/spatial.py`:
- `shape()` and `__str__` use `self.output_shape`.
- The factor-based size uses `_resize_shape_single`, the same helper as `spatial.resize`, per anchor.

The public `shape()` method is kept, because `nn/base.py` calls `layer.shape(x)`.

No other module in the file has this bug: only `Resize` defines a `shape()` method. `GridResize` also has `output_shape or self.shape`, but there `self.shape` is the stored argument.

## Tests
New file `nitorch/tests/test_nn_resize.py` (50 tests):
- factor-only output matches `spatial.resize` in values, shape and `.shape()`, for factors 2 and 0.5, every anchor, and inputs (8,8,8), (8,8) and (7,9);
- an explicit shape, with and without a factor;
- the `output_shape` override in `forward`;
- `__str__`.

`pytest nitorch/tests -k "resize or nn"`: 472 passed. Before the fix, 49 of the new tests failed (423 passed).

No docs change: `docs/cli/reference/spatial/resize.md` covers the CLI, not `nn.Resize`.
