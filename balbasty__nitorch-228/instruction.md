# Issue

**Title:** FIX(register): bool -o for @affine/@nonlin, clearer loss-group errors, simplereg false/bound, sqz -w auto

## Description

Part of #171. This is a  and #225, for issues found while working on them. I reproduced each item before fixing it.

1. **`@affine -o false` / `@nonlin -o false` wrote a file named `false`.** These options took exactly one value and had no bool conversion.
   - They now take an optional value, converted with the existing `path_or_bool`: a bare `-o`, `true`, `yes` or `1` gives the default path; `false`, `no` or `0` writes nothing; any other value is a path.
   - The default paths are now constants (`default_affine`, `default_nonlin`), unchanged in value. `check_options` already validates the templates before the fit.
2. **`simplereg -a false` / `-w false` wrote a file named `False`**, because the wrapper passed `str(False)`.
   - A new `_path_token()` helper now passes `'true'`/`'false'` explicitly.
   - `affreg` now passes `'false'` instead of `''`, so the two wrappers match. Only the `@affine`/`@nonlin -o` lines change, not the `@@fix` lines that #225 edits; the branch merges cleanly with #225.
3. **`lcc -s 2` failed with "Last unknown argument was 2".** `-s` is `--symmetric`, which takes no value, so the `2` was left over and only failed later, while `@@fix` was parsed.
   - A small `_LossGroup(cli.NamedGroup)` subclass, used only for `@loss`, now raises an error when a value is left over: `@loss lcc: unexpected value '2' after -s/--symmetric (which takes no value); did you mean --stride?`
   - The suggestion lists only long-only options with the same initial. `core/cli.py` is unchanged.
4. **`simplereg --bound nearest` was rejected by `register`.** Register's `-b` only accepts `dct2, dct1, dft, dst2, dst1, zero, replicate`.
   - *Decision:* the wrapper maps `nearest` and `border` to `replicate`, and now also accepts `replicate`. This matches `nitorch.core.bounds`, where `replicate` is the canonical name and the other two are aliases.
5. **`sqz -w auto` silently used weight 1**, because `SqueezedProdLoss` has no automatic weighting.
   - *Decision:* `auto` is now rejected with a `ParseError` that explains why. The help says `auto` means "estimated from the data", so silently using 1 was more surprising than an error.

**Not changed: `ent`.** `make_loss` calls `losses.Entropy(**kwargs)`, but nitorch does not export a class with that name; only the GMM-based entropy classes exist. Making it work needs either a histogram entropy class or removing `ent` from the loss choices and the help. I left this for your call.
