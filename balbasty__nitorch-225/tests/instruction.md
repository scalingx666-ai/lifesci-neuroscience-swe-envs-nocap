# Issue

**Title:** FIX(affreg, simplereg): stop writing the fixed image's moved output

## Description

Part of #171. This fixes the #171 item "register always writes `fix.moved`", found in #182.

**Root cause.** `register` writes `{base}.moved{ext}` for both images by default, as `register.md` documents, and `@@fix … -o false` turns the fixed one off. I checked this with a 12³ run, and that behaviour is kept. The bug was in the wrappers:
- `affreg` and `simplereg` only expose the moving image's outputs (`-x/--moved`, `-r/--resliced`);
- they built the `register` command line with nothing after `@@fix`;
- so `register`'s default always wrote `<fixed>.moved<ext>`, and there was no way to turn it off.

**Fix:** both wrappers now pass `-o false` to `@@fix`. In `simplereg` it comes after the shared preprocessing options, which still reach `@@fix`. `register` itself is unchanged, so this PR does not overlap #214.

**Docs:** a writer subagent updated `affreg.md` and `simplereg.md`:
- the outputs bullet now covers only the moving image's `.moved` output, and says the fixed image is never rewritten;
- the "equivalent `register` command" listings now show `@@fix … -o false`;
- the example output listings are updated to match.

`register.md` needs no change.

**Tests:** in the new `test_cli_affreg.py` and `test_cli_simplereg.py`:
- the arguments passed to `register` are checked, including `--bound`/`--order` still reaching `@@fix` in `simplereg`;
- small end-to-end runs check that `fix.moved` is not written while `mov.moved` is, and that `-o false -x false` writes nothing but the inputs.

The new tests fail before the fix. `pytest -k "register or affreg or simplereg"` gives 1091 passed and 40 skipped.

**Behaviour change:** `affreg` and `simplereg` no longer write `<fixed>.moved<ext>`. Plain `register` behaves as before.

**New bugs noticed, not fixed (added to #171):**
- `register @affine -o false` (and `@nonlin -o false`) writes a transform to a file named `false`, because these options have no bool conversion. `simplereg -a false`/`-w false` do the same with a file named `False`. Fixing this touches `register`'s parser, so it will follow #214.
- `simplereg --bound nearest` is probably rejected by `register`, because the `@@fix`/`@@mov -b` choices have `replicate` but not `nearest`. This comes from reading the code and was not run.
