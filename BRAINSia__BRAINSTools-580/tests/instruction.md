# Issue

**Title:** PERF: CTest disallow-build + CTEST_CUSTOM_TESTS_IGNORE for slow BCD tests

## Description

## Summary

Two complementary mechanisms to prevent slow BCD tests from blocking CI and to avoid misleading CDash entries when the build fails.

### 1. `CMake/CTestCustom.cmake.in` — `CTEST_CUSTOM_TESTS_IGNORE`

Adds all 23 BCD tests to the CTest project-level ignore list. This is the proper CTest mechanism: it is honoured by `ctest_test()` and `ctest -D Experimental*` in every context — CDash dashboard submissions, CTest scripts, and any `ctest -D` invocation — not only in GitHub Actions.

Developers can still run BCD tests locally:
\`\`\`bash
ctest -R '^BCD' -C Release
\`\`\`

### 2. `.github/workflows/build.yml` — disallow-build guard

Adds `id: inner_build` to the `ExperimentalBuild` step and `if: steps.inner_build.outcome == 'success'` to the `ExperimentalTest` step. This matches the standard CTest dashboard-script pattern:

\`\`\`cmake
ctest_build(RETURN_VALUE rv)
if(rv)
  return()  # don't run tests when the build failed
endif()
ctest_test()
\`\`\`

Without this guard, a build failure produces a CDash entry showing "0 tests run" which looks like a passing test suite rather than a broken build.

The existing `-E '^BCD'` flag is retained as a belt-and-suspenders guard: `CTEST_CUSTOM_TESTS_IGNORE` is populated only after `CTestCustom.cmake` is generated by the first `ctest_configure()` call, so the `-E` filter ensures exclusion even on a bare fresh configure.
