# Issue

**Title:** FIX(reslice, compose): displacement options and long inverse tags

## Description

Part of balbasty/nitorch#171.

## Summary
Three bugs in how `reslice` and `compose` parse and load transformations:

- **`-d FILE -n ORDER` failed** with "Argument -n does not seem to belong to a group". In `parse_transform`, the `-u` test was an `if` instead of an `elif`. After `-n` was handled, it fell into the `else` branch, which pushed the tag back to the main parser.
- **`-d FILE -u mm` crashed** in `affine_lmdiv`, because a `(..., 3, 1)` tensor is interpreted as homogeneous. A displacement is a vector, so only the linear part of the affine applies. Millimetric displacements are now converted to voxels with `inv(A[:3, :3])`. This affects 3 call sites in `reslice` and 1 in `compose`.
- **`compose --linear-inverse` (and the other long inverse forms) crashed**, because `tag.split('--inverse')` never matches `--linear-inverse` and the suffix was not stripped.

## Test plan
`nitorch/tests/test_cli_transform_options.py`:
- Parses `-d … -n 3 -u mm` with both parsers.
- Parses `--linear-inverse` and `-il` with `compose`.
- Checks that reslicing or composing with a displacement field given in mm (`-u mm`) gives the same result as the same field given in voxels.

5 of the 6 tests fail on `master`; the `-il` short form already worked. All 6 pass with this PR.
