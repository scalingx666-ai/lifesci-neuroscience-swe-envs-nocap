# Issue

**Title:** FIX(metrics): fnr, label/image groups, --append, PSNR/SSIM range and formula, rmse micro, {ext}, error handler

## Description

Part of #171. All 9 `metrics` items from #171 were reproduced and fixed.

**Fixes from #171**
1. **`fnr`:** the metric existed but was missing from `label_metrics`, so the validator rejected it.
2. **`labels`/`images` groups:** expanding a group kept the group name in the list, which raised `KeyError: 'labels'`. There was also an `'image'` typo, and the image loop iterated over the unexpanded list.
   - Groups now expand without duplicates.
   - Label and image metrics can be combined in one call. Labels are loaded as integers and images as floats; before, a single label metric made the image metrics run on long data.
3. **`--append`:** `dict.update()` returns `None`, so the file was overwritten with `null`. Tuple keys could not be written to JSON either, and a missing file raised an error. Results are now merged per metric into the existing JSON, with string keys, and the file is created if it is missing.
4. **`range` shadowing:** the parameter shadowed the builtin, which crashed psnr even without `--range`. It is renamed `data_range` in psnr and all three SSIM variants.
5. **`rmse -s micro`:** removed a stray `.ref`.
6. **Data range:** it now comes from the reference: its min/max, per channel, or global for micro. Before, it was `(0, pred.max())`. The PSNR peak is `max − min`.
7. **`ssim_gauss`:** it now uses `fwhm`; before, the FWHM was always 3.
8. **`--ssim-fwhm full`:** it is now reachable, and a bad unit raises a `ParseError`.
9. **`{ext}`:** supported in `-o`, taken from the first prediction.

**SSIM formula, checked against Wang et al. 2004**
- **All variants:** the `+C1` term was missing from the numerator, so SSIM was below 1 for identical images.
- **Windowed:**
  - `unfold` was applied only to the prediction;
  - the means did not broadcast;
  - var and cov used different N;
  - the patches did not overlap.

  It now uses a stride-1 sliding window over the valid region only, with N−1 statistics, as skimage does by default.
- **Full:** cov now uses N−1, to match `var()`.
- **Gauss:** the smoothed moments, which are already normalised, were also divided by `numel`. That is removed.

**Also:** the generic `[ERROR]` handler, commented out and not covered by #213, is restored, and errors return status 1.

**⚠️ Values that change**
- **psnr** crashed before, so there are no earlier values to compare with. With `--range MN MX`, the peak is now `MX − MN` instead of `MX`.
- **All SSIM values** change. The causes are `+C1`, the reference-based range, the sliding window with N−1 statistics, and, for the Gaussian variant, the fixed normalisation and the FWHM that is now honoured.
- **`--append` output** is `{metric: {label: value}}`.

**Docs:** writer subagents updated `docs/cli/reference/images/metrics.md`.
- It covers `fnr`, the groups, `--append`, `{ext}`, `--range`, the PSNR/SSIM formulas and the SSIM window options, and adds new examples.
- Caveats for fixed bugs were removed.
- A short Known issues list keeps the remaining limitations.

**Tests:** the new `nitorch/tests/test_cli_metrics.py` has 12 CPU tests. They check against hand-written formulas:
- fnr from TP/FN, and dice;
- the groups, and mixed calls;
- append and merge;
- rmse micro/macro;
- PSNR with a known MSE, where the reference max differs from the prediction max;
- global SSIM against NumPy;
- windowed SSIM against a brute-force sliding loop;
- Gaussian SSIM against a manual smooth-based formula, with the FWHM also passed through the CLI;
- `{ext}`;
- the error exit status.

All tests failed before the fix, and `pytest -k metric` gives 83 passed and 5 skipped.

**Not changed (added to #171):**
- `-s weighted` is ignored for image metrics and hausdorff.
- `mad` is documented as the median absolute *deviation* but computes the median absolute error.
- With several `-p`/`-r` pairs, only the first one names the output, and `--append` has no per-pair key.
- The parser mutates the argument list passed to `_cli`.
