# Issue

**Title:** FIX(cli): negative floats such as -.5 or -inf are values, not tags

## Description

Part of #171. This issue was found while working on #210.

**Root cause.** `core/cli.py` `istag` treated a dash-prefixed argument as a value only when its second character was a digit. So `-.5`, `-.5e2`, `-inf`, `-nan` and `-Infinity` were taken as tags. On `master`, `crop in.nii -c -.5` fails with `Unknown tag -.5`, and `conventions.md` told users to write `-0.5` instead.

**Fix.** A new `_isnumber(arg)` helper (`float(arg)` succeeds) is added, and `istag` now also requires `not _isnumber(arg)`. `isvalue`, `next_isvalue` and `check_next_isvalue` call `istag`, so they inherit the change. `CommandParser`, `Option` and `ListWithTags` match against explicit tag lists and already treated `-.5` as a value, so they are consistent.

**Tag conflicts:** none. I searched every dash-prefixed string literal under `nitorch/cli` for one that `float()` accepts or that is spelled inf/nan/infinity.

**Docs:** a separate writer subagent updated `conventions.md` ("What counts as a tag"):
- a tag is now "a dash-prefixed argument that is not a number";
- `-.5`, `-1e-3`, `-inf` and `-nan` are listed as values;
- a note says `autoreg` still uses its own stricter rule.

**Tests**
- `test_cli_conversions.py` gains unit cases.
  - Values: `-.5`, `-inf`, `-nan`, `-1e-3`, `-1`, `-0.5`, `-Infinity`, `-.5e2`, `-`, `1`.
  - Tags: `-o`, `--foo`, `-in`, `-n`, `-e`, `--inf`, `-.`, `-.o`, `-infx`.
- It also gains an end-to-end case: `crop in.nii -c -.5 -1e-3 -inf -o out.nii` gives the centre `[-0.5, -0.001, -inf]`.
- All `nitorch/tests/test_cli_*.py`: 314 passed. Other tests that import CLI parsers: 233 passed, 3 skipped.

**Behaviour change:** any dash-prefixed argument that `float()` accepts is now a value wherever `istag`/`isvalue` is used. Arguments that were already values are unaffected.

**Related, not changed here** (added to #171):
- `next_istag`'s empty default symbol, which misreads file names in `reslice`/`compose` (separate PR in progress).
- `autoreg`'s own `istag`, which is `startswith('-')`, so every negative number is a tag there. To be fixed after #205.
