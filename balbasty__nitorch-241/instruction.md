# Issue

**Title:** FIX(metrics): hausdorff is inf for a missing label and excluded from averages; per-channel distance transform

## Description

Part of #171. This implements your decisions on two issues found in #236. Each was reproduced first.

1. **Missing label.**
   - **Bug:** `_hausdorff` returned 0 for a label with no prediction voxels, and that 0 went into the macro and weighted averages. Labels were taken from the reference only, so a label present only in the prediction was never scored. If every label was missing, micro crashed on `torch.cat([])`.
   - **Labels:** they are now the union of the reference and prediction labels, minus `--exclude`.
   - **Missing labels:** a label missing from either image gets `inf`. It is left out of the macro, weighted and micro averages, and one `UserWarning` names the excluded labels. If no label remains, all three averages are `inf`.
   - **Micro:** it now pools only the labels present in both images, which makes it well defined. It also keeps the `inf` distances of a label found only in the prediction from making micro `inf`.
2. **Per-channel distance transform.**
   - **Bug:** `euclidean_distance_transform(~r)` was called without `dim`, so on the stacked `[C, X, Y, Z]` volume (several `-p`/`-r` pairs, or a 4D file) the channel axis was treated as spatial, and distances leaked across channels.
   - **Fix:** it is now called with `dim=ref.dim()-1`. Each label's distances are still pooled over the channels.
   - Distances remain in voxels; the code never applied the voxel size.

**JSON:** `inf` is written as `Infinity`. This is not strict JSON, but Python's `json` reads it back, so `--append` still works. The format is unchanged.

**Docs:** a writer subagent updated the Hausdorff section and the micro paragraph of `metrics.md`:
- the union of labels;
- `inf` for a missing label, excluded from the averages;
- per-channel distances.

**Tests** (`test_cli_metrics.py`, checked against scipy `distance_transform_edt` per channel):
- `test_hausdorff_missing_label_is_inf`;
- `test_hausdorff_label_only_in_prediction_is_inf`;
- `test_hausdorff_all_labels_missing`, for `hausdorff` and `hausdorff95`;
- `test_hausdorff_4d_per_channel` and `test_hausdorff_pairs_per_channel`.

All 5 fail before the fix. After it, the file gives 23 passed, and `pytest -k "metric or cli"` gives 843 passed and 10 skipped.

**Behaviour changes**
- A missing label is reported as `inf` instead of 0, so averages can go up.
- Labels present only in the prediction now appear in the output.
- Results for 4D files and multi-pair inputs change, and are now correct.

**New issues noticed, not fixed (added to #171):**
- Hausdorff is still directed, from prediction to reference. This is documented, but it is not the usual symmetric distance.
- A channel where the prediction has a label but that channel's reference does not gives `inf` for the whole label.
- Overlap metrics never score labels found only in the prediction.
- The macro average of the overlap metrics would divide by zero if no reference label remains after `--exclude`.
