# Issue

**Title:** FIX(vexp): honour -inv, and convert displacements to mm without translation

## Description

Part of balbasty/nitorch#171.

## Summary
- **`-inv` had no effect.** The CLI always called `vexp(..., inverse=False)`. Separately, a bare `-inv` was parsed as `False`. `-inv` now means `True`, and it accepts an optional boolean (`-inv false`, `--inverse 0`).
- **`-u mm` was wrong for displacement fields.** Displacements went through `affine_matvec`, which adds the translation of the orientation matrix. A displacement is a vector, so only the linear part `A[:3, :3]` should apply. Transformation fields (`-t t`) are coordinates and still use the full affine.

## Test plan
`nitorch/tests/test_cli_vexp.py`:
- Parses the different spellings of `-inv`.
- Checks that `vexp -inv v` equals `vexp(-v)`, and that it differs from the forward exponential.
- Checks that, with an affine that has a translation, `-u mm` gives the voxel displacement scaled by the voxel size.

3 tests fail on `master` and all 7 pass with this PR.
