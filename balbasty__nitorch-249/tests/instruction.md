# Issue

**Title:** FIX(spatial.resize): one output-size rule per anchor, first/last stay inside the FOV; bound for out-of-FOV samples

## Description

Part of #171. This implements your decisions on `resize -g` and the anchors.

**1. Output size, the same everywhere**
- A shared helper is now used by `spatial.resize`, `resize_grid` and `affine_resize` for every anchor, so the image shape and the affine always agree.
  - **`centers`/`edges`:** `floor(N·f)`, so 10 × 2 gives 20.
  - **`first`/`last`:** `floor((N−1)·f) + 1`, so 10 × 2 gives 19, and 10 × 1/3 gives 4, which matches `vol[::3]` as the docstring claimed.
- Before, `first`/`last` with f > 1 put the last output voxel outside the input field of view.
- An explicit shape still wins.
- A float guard (1e-6) snaps values that are almost integers, so 100 × 0.57 gives 57.
- `affine_resize` used `round(N·f)` for `c`/`e`; it now uses the same rule as `resize`.

**2. Out-of-FOV samples.** `centers` never samples outside the field of view; `edges` samples up to half a voxel outside when upsampling.
- **`resize_grid` (`-g`):** it now defaults to `bound='dct2'` with `extrapolate=True`. `grid_pull`'s default `extrapolate=False` zeroed out-of-FOV samples whatever the bound.
  - Grids (`type='grid'`) are resized as displacements: the identity is subtracted, the displacement is resized, and the identity is added back. Without this, dct2 would reflect the absolute coordinates.
  - Callers can still pass `bound=`/`extrapolate=` themselves.
- **`nitorch resize` (images):** it now passes `extrapolate=True`, so `-b` (default dct2) is used for out-of-FOV samples too. The `spatial.resize` library default is unchanged.
- **Also fixed:** `resize_grid` unpacked the spatial shape one axis short, which broke grids with more than one batch dimension.

**⚠️ Shape changes (intended)**
- `reslice -vx` and uniseg use the `first` anchor with a voxel size, so their output size follows the new rule. For example, 256 voxels from 1 mm to 0.5 mm gives 511 instead of 512, whose last voxel was outside the field of view.
- `nn` SynthPreproc and RandomLowRes intermediate shapes can change by one voxel. Their final shapes are explicit, so outputs keep their size.
- The `c`/`e` unification changes `affine_resize` callers by one voxel when N·f has a fractional part of .5 or more: the autoreg pyramid levels and the estatics/greeq level shapes. For example, 255 voxels halved gave 128 and now gives 127. Those callers pass that shape explicitly to `resize`, so the image and its affine stay consistent. Nothing found relies on the old sizes.
