# Issue

**Title:** REFACTOR(cli): share setup_device; meanspace computes name parts once

## Description

Part of #171. This follows your decision to share `setup_device`. Behaviour does not change.

**How the four copies differed:**
- **register** and **uniseg** had identical bodies:
  - `'gpu'` without CUDA warns "CUDA not available. Switching to CPU." and drops the index;
  - `'cpu'` with a non-zero `ndevice` sets the thread count;
  - any other value raises an `AssertionError`.
- **meanspace** has the same logic, but no assert, so any value other than `'cpu'` means CUDA.
- **denoise_mri** works differently. It takes a torch device string (`'cpu'`, `'cuda:1'`), falls back to CPU with the same warning, returns `torch.device(...)`, and never sets the thread count.

All four default to CPU.

**Change:** the new `nitorch/cli/utils.py` holds `setup_device(device='cpu', ndevice=None, *, strict=True, torch_string=False)`.
- `strict=False` reproduces meanspace's behaviour.
- `torch_string=True` reproduces denoise_mri's behaviour.
- Each command keeps a `setup_device` with its original signature that calls the shared one, so existing imports and monkeypatches still work. `test_cli_meanspace.py` patches `meanspace_cli.setup_device`.
- Imports that were no longer used are removed in meanspace and denoise_mri.

**meanspace:** the absolute paths and `{dir}`/`{base}`/`{ext}` are now computed once per input, before the reslice loop, instead of being reassigned inside it. `-o` uses the first input's parts, as before.

**Tests:**
- The new `nitorch/tests/test_cli_setup_device.py` covers:
  - the CPU default, and `--cpu 1` setting the thread count;
  - `--gpu` with and without CUDA, with the fallback warning and the index not used as a thread count;
  - strict and lenient modes, and torch strings;
  - each command calling the shared function with the right arguments.
- `test_resliced_names` in `test_cli_meanspace.py` checks `{dir}/{base}{ext}` naming with two inputs in different directories.
- The touched test files give 84 passed and 1 skipped. `pytest -k "cli or register or uniseg or meanspace or denoise"` gives 1771 passed, 44 skipped and 0 failed.

**Left alone:** `denoise` and `metrics` each have their own copy of the register-style function. They were outside the four commands named in #171, and each could later become a one-line wrapper.
