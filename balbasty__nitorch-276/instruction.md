## Summary
The default test workflow only builds the TorchScript backend, so compiled-only bugs (the 56 failures fixed in #275) went unnoticed. This adds `.github/workflows/test-compiled.yml`, which:
- builds the C++ backend (CPU) in development mode: `NI_COMPILED_BACKEND=C NI_USE_CUDA=0 NI_COMPILE_WORKERS=4 pip install --no-build-isolation -e .`;
- fails early if the compiled backend is not the one in use (`nitorch.compiled_backend == 'C'`);
- runs the same test suite as the default workflow, with the same pytest options.

**It only runs when files it depends on change**, on pull requests to master and pushes to master:
- `nitorch/_C/**`: the C++ sources and their Python bindings;
- `nitorch/spatial/**`: the Python code that dispatches to the compiled kernels, e.g. the `_c_supports` fallbacks and the dtype handling in `_grid.py`;
- the build files: `setup.py`, `setup_cext.py`, `setup.cfg`, `buildtools.py`, `pyproject.toml`;
- the workflow itself.

It can also be started manually (`workflow_dispatch`).

There is a single configuration (Ubuntu 24.04, Python 3.12, torch 2.5.1, CPU), because the build takes a while. The timeout is 120 min.

This PR touches the workflow file, so the new job should run on it. That's the test that the build works on the runners.

The existing manual-only `build.yml` and `test_pushpull_C.yml` are unchanged.
