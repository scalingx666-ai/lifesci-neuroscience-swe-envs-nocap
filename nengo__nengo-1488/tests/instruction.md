# Issue

**Title:** Travis updates

## Description

**Motivation and context:**
<!--- Why is this change required? What problem does it solve? -->
<!--- If it addresses an open issue, please link to the issue here. -->

This adds some new quality of life stuff to our Travis builds.  

- c955c80 makes sure that we aren't accidentally installing a different version of numpy than we thought.  E.g., previously if we had set $NUMPY=1.3, but our internal nengo requirement was `numpy==1.10`, then we'd install `numpy==1.10` overtop of 1.3, giving us the mistaken impression that we were successfully testing 1.3.
- 8f79e5e changes the build environment to `minimal`.  Not that important, but means a slightly smaller docker image when spinning up a new job.
- 79996d9 activates TravisCI's caching functionality (so that we can reuse our python environment rather than building it from scratch this time).  However, testing this out shows that it doesn't offer a significant improvement to the build time (it did in NengoDL, but NengoDL has more dependencies to install).  And in the case of cache misses, it increases the build time.  I'll play around with it a little bit, but probably we don't end up using it.
- c5a6049 sets up automatic PyPI deployment for tags, with some error checking (so making new releases requires less manual effort).  It will also build test releases for branches named `release-candidate-x.y.z`; you can see an example here https://test.pypi.org/project/nengo/, generated by this build https://travis-ci.org/nengo/nengo/builds/452386601
