# Issue

**Title:** FIX(cli): next_istag default symbol; reslice no longer drops stray values silently

## Description

Part of #171. I found this while working on #211.

**Root cause.** `core/cli.py` `next_istag(args, symbol='')` passed an empty symbol to `istag`. Every string starts with `''`, so any argument of length ≥ 2 whose second character isn't a digit, such as `extra.nii` or `vel.json`, counted as a tag. `istag` itself already defaults to `'-'`. The only callers are the `reslice` parser (lines 128 and 159) and the `compose` parser (line 127). `autoreg` has its own helpers, and nothing passes `'@'`.

**Concrete misparse.** Inside the per-transform loops this was harmless. The `reslice` main loop, though, does `if not cli.next_istag(args): break`.
- Most stray values were taken for tags and raised "does not seem to belong to a group".
- Values whose second character is a digit, or that are only one character long, ended parsing early and were **silently dropped**. `reslice in.nii -l aff.lta x1.nii` and `reslice in.nii -l aff.lta b` both "succeeded" and ignored the last file.

**Fix (3 lines)**
- `next_istag` now defaults to `symbol='-'`.
- `reslice`'s main loop raises `ParseError('Value X does not seem to belong to a tag.')` instead of `break`, as `compose` already does. This second change is needed: with only the new default, every stray value would be silently dropped.

**Tests**
- `test_cli_conversions.py` gains unit tests for `istag`/`next_istag`:
  - dash tags are recognised;
  - file names, `x1.nii`, `b`, `-1`, `-0.5` and `-` are not;
  - an empty list returns False;
  - a custom `'@'` symbol works.
- `test_cli_transform_options.py`:
  - `reslice` rejects a stray value after `-l`, after `-d … -u mm`, and after `-v vel json`;
  - `-o`/`-t` after a transform still parse;
  - `compose` rejects stray values.
- Before the fix, 8 of these fail. After it, all of `nitorch/tests/test_cli_*.py` passes (322 passed).

**Behaviour change:** `reslice` now always rejects a stray value after the first tag. Before, some were silently ignored, and others failed with a different message.

**Docs:** none needed, since this only turns a silent mistake into an error.
