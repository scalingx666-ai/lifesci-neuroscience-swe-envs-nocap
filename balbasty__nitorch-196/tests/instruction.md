# Issue

**Title:** FIX(convert): --metadata, MGH dtype promotion, voxel_size/tr overrides, intercept

## Description

Part of #171.

- **`--metadata`** was listed in the help, but the parser only knew `-m`/`--meta`. It now accepts all three.
- **MGH dtype promotion** was decided from the `{ext}` placeholder, i.e. the input's extension or `-f`. It is now decided from the resolved output filename, so converting `nii` to `-o x.mgz` with int8 data no longer fails in nibabel.
- **`voxel_size` / `tr` overrides were ignored.** These changes are in the babel writer (`io/volumes/babel/{metadata,array}.py`):
  - `affine` is now applied before `voxel_size` in `metadata_to_header`, so a `voxel_size` override rescales the affine instead of being undone by the affine copied from the template.
  - When `affine`, `tr` or `time_step` is set explicitly, the related fields inherited from the template no longer override it.
  - NIfTI time steps are stored in the given unit (seconds by default, ms with a suffix), and the xyzt time unit is set to match. Before, they were always converted to ms while the unit was left unchanged. MGH still stores TR in ms.
- **`inter=`** set the slope because of a typo in `metadata.py`. It now sets the intercept.

**Docs:** removed the caveats about these bugs from `convert.md`.

**Tests**
- The new `nitorch/tests/test_cli_convert.py` has 9 tests. On `master`, 7 fail and 2 pass; with this PR, all 9 pass.
- Because this touches the shared NIfTI/MGH writer, I also ran the **full suite** locally on this branch: 2719 passed, 107 skipped.

**Behaviour change:** NIfTI headers written with a TR now store it in seconds with a matching `xyzt` unit, where before it was in ms with a stale unit. Readers that honour the unit see the same value.
