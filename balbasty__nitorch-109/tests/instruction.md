# Issue

**Title:** FIX(core): support SciPy logm without the removed disp argument

## Description

## Summary
Newer SciPy removed the `disp` argument from `scipy.linalg.logm`, and `logm` now returns only the matrix. Because `nitorch/core/_linalg_logm.py` called `logm(x, disp=False)[0]`, the matrix log raised `TypeError` in both its forward and backward passes, and every `nitorch register @nonlin ...` run crashed.

- Added a `_scipy_logm_nowarn` helper. It tries the old signature (`disp=False`), falls back to `logm(x)` on `TypeError`, and handles either return type.
- The helper keeps the original "no warning" behaviour by suppressing the accuracy warning with `warnings.catch_warnings`.
- I grepped the repo for `disp=` and found no other scipy `logm`/`sqrtm` callers. The `disp=False` in `tools/affine_reg/_core.py` goes to `scipy.optimize` and is unaffected.

## Tests
New file `nitorch/tests/test_linalg_logm.py`:
- Checks that `expm(logm(A))` gives back `A` for batches of random rotations and random affines.
- Checks that the `logm` backward pass returns finite gradients.
- Runs `nitorch register @loss mse ... @affine rigid @nonlin svf` end to end on a tiny synthetic 3D pair.

With SciPy 1.18.1: 4 passed after the fix. Before the fix, 3 of the 4 failed with `TypeError: logm() got an unexpected keyword argument 'disp'`.

## Found, not fixed here
- There are `SyntaxWarning: invalid escape sequence` warnings in docstrings in `nitorch/_C/_ts/pushpull.py` and `nitorch/core/linalg.py`.
- The package has no `nitorch/__main__.py`, so `python -m nitorch` does not work.
