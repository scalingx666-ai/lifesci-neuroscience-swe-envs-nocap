## Description

Part of #171. This is a , for a bug found while working on that PR.

- **No size option.** With none of `-f`, `-v` or `-s`, `resize` used to raise an uncaught `ValueError` in `write_data`. It now raises a `ParseError` at parse time, the same way the `-f`/`-v` check from #193 does: the command prints the usage and `[ERROR] Need at least one of -f/--factor, -v/--voxel-size or -s/--shape.`, and writes nothing.
- **Generic error handler.** The commented-out `except Exception` handler in `resize` is restored, in the same style as `compose`, `orient`, `reorient` and `vexp`. A runtime error, such as a missing input file, now prints a one-line `[ERROR] <message>` instead of a traceback.

- it says that at least one size option is required;
- the old "Exactly one of the following is needed" was already wrong, because `-s` combines with `-f`/`-v`. It now reads "At least one of the following is required".

**Tests:** I added `test_resize_no_size_option` to `nitorch/tests/test_cli_resize.py`.

- It fails before the fix, and the whole file passes after it (5 passed).

`reslice` has the same commented-out handler; it is listed in #171 with the other commands that have one.
