# Issue

**Title:** FIX(compose): honour -n/--order for displacement fields

## Description

Part of #171. This bug was found while removing the docs caveats in #179.

`compose -d FIELD -n ORDER` parsed the order into `opt.order`, but `compose/main.py` read `trf.spline`, a field that was always `1`. So `-n` was silently ignored, and displacement fields were always interpolated linearly. The `-u` `if`→`elif` fix in #176 made `-n` parse, but the value still never reached the interpolation.

- `compose/main.py` now uses `trf.order`, as `reslice` does.
- The unused `spline` fields are removed from `Displacement`/`Velocity`.
- Docs: removed the `-n` caveat in `compose.md`.
- Test: `test_compose_displacement_order_is_used` composes a random field onto a finer target with `-n 1` and with `-n 3`, and checks that the results differ. It fails before the fix and passes after it. The whole `test_cli_transform_options.py` file passes (7 tests).

Heads-up: this PR and #179 both edit the same `compose.md` options table. Whichever merges second will need a small rebase, and I'll handle it.
