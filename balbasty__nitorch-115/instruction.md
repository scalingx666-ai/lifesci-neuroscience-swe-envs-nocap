# Issue

**Title:** ENH(core): Gauss-Newton histogram Hessian for any spline order

## Description

## Summary
- `_jhistc_backward2` / `_histc_backward2` (nitorch/core/_hist.py) now accept any spline order >= 1. Only the order-1 Hessian kernel exists. For order k != 1, its output is rescaled per component so that its average over sub-bin position matches the expected Gauss-Newton curvature of the order-k histogram:
  - 2D (diag and full variants): x component gets `(d_kx·w_ky)/(d_1·w_1)`, y component gets `(w_kx·d_ky)/(w_1·d_1)`.
  - 1D: `d_k/d_1`.
  - Here `w_k = ∫B_k²` and `d_k = ∫(B_k')²`. They are computed once, exactly, by piecewise Gauss-Legendre quadrature of nitorch's own `Spline.weight/grad`, then cached (orders 1 to 7). The docstrings say this is an approximate, position-averaged Hessian.
- Order 0 raises `NotImplementedError` with a clear message.
- Order 1 output is bitwise unchanged.
- Fixes in `HistCount.backward2`: it applied the intensity-to-bin affine to its output instead of multiplying by `(bins/(max-min))²`; it called `h.reshape(h, ...)`, which crashes; and the default min/max had the wrong broadcasting shape.
- Fix in 1D `_histc_backward2`: `h.unsqueeze(-1)` passed the bins as channels to `iso1_grad2_*_1d`, which gave a wrong `(b, bins, n)` output. It now uses `unsqueeze(1)`.
- Nothing in `mi.py` or the register parser blocks order > 1 for GN; the parser default is already 3. #107's help note "GN needs order 1" (and its default change to 1) becomes obsolete once this is merged.

## Tests
`nitorch/tests/test_hist_hess_order.py` covers:
- the constants (k=1: 2/3, 2; k=2: 0.55, 1; k=3: 151/315, 2/3)
- order 1 output bitwise equal to the raw kernel
- order 0 raising the error
- joint orders [2,2], [3,3], [2,3], [3,1], and 1D orders 2 and 3: the rescaled Hessian averaged over 400 random samples is within 10% of the exact GN term (autograd jacobian, then Σ H J²)
- 1D order 1 exactly equal to the exact GN term
- `HistCount.backward2` against the chain rule
- end to end: `nitorch register @loss mi --order 3 ... @affine translation @@optim gn` recovers a synthetic shift

Result: 108 passed (`-k "hist or mi or register"`).

## Found, not fixed here
