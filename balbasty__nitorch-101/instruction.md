# Issue

**Title:** FIX(build): compile the C++ extension with recent setuptools/PyTorch

## Description

## Summary

The C++ extension (`NI_COMPILED_BACKEND=C`) could not be built with current tooling. There were three independent failures:

1. **`buildtools.py`**: recent versions of setuptools' vendored distutils removed `dry_run` from the compiler constructors (`CCompiler.__init__(self, verbose=False, force=False)`). Building failed with `TypeError: Compiler.__init__() takes from 1 to 3 positional arguments but 4 were given`. `dry_run` is now passed only when the constructor accepts it, both for the default compiler and for `NVCCompiler`.
2. **`setup_cext.py`**: recent PyTorch headers require C++20 (`ATen.h: #error C++20 or later compatible compiler is required`), but the build used `-std=c++17`. The required standard is now read from the installed `ATen.h`, falling back to the previous rule (c++17 for torch 2.x, c++14 before). This applies to both the C++ and nvcc flags.
3. **`setup.py`**: the exact torch pin included the local version label (`torch==2.15.0+cu132`). That label isn't always part of the installed package's metadata (here `2.15.0`), which made pip's resolver fail. The pin now drops the label (`torch==2.15.0`, which still matches `+cpu`/`+cuXXX` installs).

## Testing
`NI_USE_CUDA=0 NI_COMPILED_BACKEND=C pip install --no-build-isolation -e .` with python 3.11, torch 2.15, setuptools 84:

- this PR: builds in ~13 min, `from nitorch._C import spatial` works, `COMPILED_BACKEND: C`, and `nitorch/tests` + `nitorch/io/tests` give 208 passed, 2 failed. The 2 failures are `test_babel`, which fail on master too and are fixed by #92/#97.
