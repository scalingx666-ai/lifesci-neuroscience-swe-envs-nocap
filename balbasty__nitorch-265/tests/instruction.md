# Issue

**Title:** FIX(spatial.shoot): allow backpropagation through shoot

## Description

Part of #171.

On master, `spatial.shoot` failed under autograd for every combination of `return_inverse`, `displacement` and `fast`, in 2D and 3D, with "Output 0 of Permute/Select is a view and is being modified inplace".

## Cause
With the TS backend, the pull/push kernels end with `out.reshape(...)`. So the output of `GridPull.forward` (`nitorch/_C/grid.py`) is a view created inside a custom autograd Function, and autograd forbids modifying such a view in place. Two in-place ops in `nitorch/spatial/_shoot.py` did exactly that:
- `disp = _pull_grid(disp, id - vel, ...).sub_(vel)`, which is the first failure in every case;
- `disp += id`, which is the second failure when `displacement=False`.

## Fix
When a graph is being built (grad enabled and `vel` or `greens` requires grad), `shoot` uses out-of-place `disp - vel` and `disp + id`. They give the same values. With autograd off, the original in-place code runs, so outputs are bit-for-bit unchanged. `test_shoot_default_is_unchanged` passes as is.

The alternative was to return a non-view from `GridPull`/`GridPush`. Those are shared grid ops, so that would add a copy to every pull/push call on the TS backend; the local fix allocates only when autograd is in use.

## Impact
- Fixed: training through `nitorch.nn` geodesic shooting with `approx=False`, and any user code that backpropagates through `spatial.shoot`.
- The `approx=True` path (`_ApproximateShoot`) runs `shoot` without a graph, so it was never affected.
- The registration and qMRI callers appear to use hand-written Gauss–Newton gradients, not autograd.

## Tests
New file `nitorch/tests/test_shoot_autograd.py` (25 tests, about 25 s):
- the backward pass runs for all 8 flag combinations, in 2D, 3D and batched 2D;
  - the gradient is finite and nonzero;
  - the output with grad on is bitwise equal to the output under `no_grad`;
- `torch.autograd.gradcheck` in double on a 6×5×2 field with 2 steps passes.

`pytest nitorch/tests -k "shoot or grid_inv"`: 191 passed, 3 skipped (before: 166 passed, 3 skipped). It was tested locally on the TS backend with torch 2.x; CI also runs torch 1.13.1.

## Not fixed here
`inversion='push'`/`'newton'` under autograd still fails, inside the shared multigrid solver (`restrict` in `nitorch/spatial/_solvers.py`, `x.mul_(...)`). Making the iterative inversion differentiable is a separate design question. The default `inversion='default'` is fixed.
