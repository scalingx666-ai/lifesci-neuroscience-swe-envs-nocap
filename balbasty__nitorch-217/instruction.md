# Issue

**Title:** FIX(vopt): pairs given in one direction, partial weights, deterministic subject order

## Description

Part of #171. This is a , for issues found while working on that PR. All the fixes are in `nitorch/spatial/_svf_optimal.py`.

1. **Pairs given in one direction only.** `fit_unweighted` and `fit_weighted` called `svf.setdefault((b, a), -v)`, and `fit_weighted` also called `weights.setdefault(...)`, while iterating over the same dict. Any pair given in one direction only therefore raised "dictionary changed size during iteration". This also broke the second example in `vopt.md`.
   - A new `complete_pairs()` helper works on a copy of the dict, and fills in each missing direction as `-v`, with the same weight.
   - The system size `K` was computed once, from the *original* number of pairs. It is now recomputed after completion; otherwise the matrices would have been too small.
2. **Only some pairs weighted.** The missing weight was filled with a 0-d `meanw`, and `h.shape[-1]` then raised `IndexError`. It is now an isotropic `(*shape, 1)` field equal to the mean of the given weights' diagonal entries.
3. **Subject order.**
   - `labels = list(set(...))` gave an order that is not deterministic for string labels.
   - The `vopt` and `optinorm` CLIs rebuilt that list separately to name output files, so fields could be saved under the wrong subject's name.
   - A new public `svf_labels(pairs)` sorts the labels when they are comparable, and otherwise keeps their order of first appearance. `optimal_svf`, `vopt/cli.py` and `optinorm/main.py` now all use it.
4. **Stray prints.** The "fit", "slice: k" and "regularize" messages are now shown only when `optimal_svf(verbose=True)`.

**Docs:** a separate writer subagent updated `vopt.md`:
- one-direction pairs and the copied reverse weight;
- partial weights;
- the subject order (labels sort as strings, so `10` comes before `2`);
- the sentence about progress messages is removed.

**Tests:** the new `nitorch/tests/test_svf_optimal.py` has 8 tests.
- One-direction pairs match explicit two-way pairs, unweighted and weighted.
- Consistent pairs (v01 + v12 = v02) are reproduced exactly.
- Mixed weights give the same result as all unit weights.
- String labels are sorted and assigned to the right fields, and the `svf_labels` rules are covered.
- Nothing is printed by default.
- Before the fix, the first 4 fail with the `RuntimeError`. `pytest -k "svf or vopt or optinorm"` gives 48 passed and 4 skipped.

**Behaviour changes**
- Pairs given in one direction now work, with or without `-w`.
- Output subjects come in sorted label order.
- `vopt` prints no progress messages.
