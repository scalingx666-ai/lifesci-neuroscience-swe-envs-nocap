# Issue

**Title:** [ENH] Support renamed binary (fsl-cluster) in FSL Cluster interface

## Description

### Summary

Update the `fsl.Cluster` interface to use the `fsl-cluster` executable when available, while preserving compatibility with old FSL installations where the command were only exposed as `cluster`.

### Motivation

Recent FSL conda installations do not create the command wrappers provided by standard FSL installations. In particular, installing `fsl-cluster` through conda provides the `fsl-cluster` executable, but the `cluster` alias will be missing.
This causes the Nipype `Cluster` interface to fail.
I wrote to the FSL developers and @pauldmccarthy confirmed that this is expected behaviour: wrapper scripts such as `cluster -> fsl-cluster` are only generated by the standard FSL installation workflow. For custom/conda installations, users may need to create the wrappers manually or use the original command names directly.

### Changes
The `Cluster` interface now dynamically selects the executable:
```python
_cmd = "fsl-cluster" if which("fsl-cluster") else "cluster"
