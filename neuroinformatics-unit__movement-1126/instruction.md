**Why is this PR needed?**

The napari plugin now supports manually correcting tracked data and saving it back to movement's native format. This includes moving and removing keypoints, flagging edited points, navigating edits with a timeline, resetting edits, and saving the corrected dataset. None of this is documented in the user guide yet.

**What does this PR do?**

Adds a new "Edit tracked data" section to the GUI user guide (`docs/source/user_guide/gui.md`), placed between "Load tracked data" and "Define regions of interest" to match the order of the widget's collapsible menus.

It covers:

- **Overview:** the parts of the GUI involved in editing (viewer, layer controls, `Edit tracked data` menu, edit timeline, `Save tracked data` menu), with an annotated screenshot.
- **Select keypoints:** clicking, Shift+clicking and box-selecting with the *Select points* tool, and a note that editing is disabled when the frame slider controls a non-time dimension (reordered axes or 3D view).
- **Edit types:**
  - **Move keypoints:** moved points are shown as rings, their confidence is set to `NaN`, and hovering shows `edited: True`.
  - **Remove keypoints:** with the ✕ button or the `Delete`, `Backspace` or `1` keys.
  - The tracks layer stays in sync with the points layer.
- **Edit timeline:** a solid line marks each edited frame and a dashed line marks the current frame. Click a solid line to jump to that frame, scroll to zoom, drag to pan, double-click to reset. With multiple individuals, `Display individuals` splits the timeline into one row per individual.
- **Reset edits:** the `Reset current frame` and `Reset all frames` buttons, and what they restore when resuming a saved session.
- **Save edits:** saving to netCDF via the `Save tracked data` menu, what the saved dataset contains (including the boolean `edited` variable, and which keypoints/individuals get dropped), and resuming an editing session by reloading the file.

**Screenshots and videos**

The editing screenshot and the five videos (`napari_select_keypoints.mp4`, `napari_move_keypoints.mp4`, `napari_remove_keypoints.mp4`, `napari_edit_timeline.mp4`, `napari_edit_timeline_individuals.mp4`) are generated by `docs/make_gui_screenshots.py` (from #1162), replacing the hand-made GIFs.

The script now also records videos. Each video frame is still a napari `viewer.screenshot(canvas_only=False)`, as for the images. The new `Recording` class adds:

- **Driving the GUI:** real mouse and key events (clicks, Shift+clicks, drags, scrolls, double-clicks, key presses) are sent to the widgets with Qt's `QTest`, so napari and the movement widgets respond as they would to a user.
- **Drawing:** after each step, the window is grabbed and Pillow draws the mouse pointer and a caption on it, like the labels on the screenshots.
- **Encoding:** the frames are written to an H.264 MP4 at 15 fps with `imageio` (using `imageio-ffmpeg`).

The videos use the sample octagon dataset, so anyone can regenerate them. The contributing guide mentions the videos in the "Updating GUI screenshots" section.
