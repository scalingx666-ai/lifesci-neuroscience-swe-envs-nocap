# Issue

**Title:** CI: test datalad-container with Docker's classic image store, for now

## Description

The `datalad-container` job of the "Extensions" workflow fails ATM, e.g. in [this run for #7995](https://github.com/datalad/datalad/actions/runs/43176751099/job/131042739674?pr=7995), with 3 failures in `adapters/tests/test_docker.py` (`test_save_and_run`, `test_containers_run`, `test_load_multi_image`).

Docker >= 29, as on `ubuntu-latest` runners, defaults to the containerd image store, under which the docker adapter of datalad-container does not find the images it loads (their IDs are no longer the digests of their configurations).

This PR does what datalad-container's own CI already does (datalad/datalad-container@b6fa877): switch the daemon to the classic image store, which Docker 29 still provides, by setting `"containerd-snapshotter": false` in `/etc/docker/daemon.json` and restarting it.

- The logic is in a new `tools/ci/docker-use-classic-image-store.sh`. It has no `sudo` calls inside; the workflow runs the whole script under `sudo`.
- The step runs only for the `datalad-container` matrix entry, and carries a TODO to remove it once the adapter supports the containerd image store.
- The script fails if the store did not switch, and emits a warning annotation on Docker >= 29 so that the workaround stays visible.
- The script is added to the list checked by the shellcheck workflow.

Only the "Extensions" (and shellcheck) results matter here: `datalad-container` should pass, and the other extensions should be unaffected. Other CI runs for this PR were cancelled on purpose.
