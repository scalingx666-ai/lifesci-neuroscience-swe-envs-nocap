# Issue

**Title:** FIX(epic): -p clash, default device, default output dir, readout along axis 0, optional -f

## Description

Part of #171. I reproduced each item before fixing it.

1. **`-p` was registered twice**, for polarity and for penalty. `-p 3` failed with "Not enough arguments for option polarity", so the penalty could only be set with `--penalty`. It is now long-only, which matches the help, and `-p` stays polarity.
2. **The default device was the string `'cpu'`**, so `get_device` crashed when unpacking it whenever neither `--cpu` nor `--gpu` was given. The default is now `('cpu', None)`.
3. **The default output went to `/`** when the input had no directory part: `fileparts('x.nii')` gives an empty dir, and `{dir}{sep}…` then becomes `/x_epic.nii`. A new `_fileparts` helper uses `.` instead, in all three output branches.
4. **A readout along voxel axis 0 was broken.** In `tools/denoising/epic.py`, `readout - ndim if readout > 0` left a readout of 0 unchanged, so the code moved the *echo* dimension instead of the first spatial axis. Every `readout >= 0` is now converted, and out-of-range values raise an error.

   Two related bugs in the CLI's `get_readout` are also fixed:
   - it used `len(shape)` of a possibly 4D input, and its largest-axis guess could pick the echo axis;
   - letters naming the opposite end of an axis (`-d l`/`p`/`i` on a RAS volume) crashed with a `TypeError`. Both ends of an axis now match, and an unknown letter gives a `ParseError`.
5. **`-f` (field map).** *Decision:* it stays **optional**. `epic(fieldmap=None)` works in all modes and only denoises, without distortion correction. The help now shows `[-f FIELDMAP]` and explains this. Enforcing `-f` would take two lines, if you prefer that.

**Also fixed:** `map_files(tensor, nobatch=True)` called `files[0]` on a `(*spatial)` fieldmap tensor, which silently dropped the first spatial dimension. This affected only Python API callers passing a tensor. The `topup` docstring left over in `epic`'s `_cli` is fixed too.

**Docs:** a separate writer subagent updated two pages.
- `epic.md`:
  - `-p`/`--polarity` and the long-only `--penalty`;
  - `-f` is optional;
  - the `{dir}` default for bare file names;
  - the device is now optional;
  - either end of an axis is accepted for `-d`, and a readout along any axis works;
  - the examples no longer need `--cpu`.
- `qmri/index.md`: removed the note that `epic` needs `--cpu`/`--gpu`.

**Tests:** the new `nitorch/tests/test_cli_epic.py` has 22 CPU-only tests.
- Parser tests for `-p`/penalty, the device, and `-f`.
- The default output directory, and a run with no field map.
- `get_readout` for every letter, for 4D input, and for the largest-axis default.
- Equivariance: readout=0 matches readout=−3 exactly, and matches readout=2 on axis-transposed data within 1e-3. Readouts 0 and 2 on the same data differ by about 0.14, so the check is meaningful.
- Before the fix 15 tests fail; after it all 22 pass. An end-to-end run (`nitorch epic echo.nii -f fm.nii -d l`, a 4D file with no directory part and no `--cpu`) wrote `./echo_epic.nii`.

**Behaviour changes**
- `-p` no longer means penalty; it never actually worked as one.
- `epic(readout=k)` treats any `k >= 0` as a spatial index.
- A tensor fieldmap passed to `epic()` is no longer sliced.

**Not changed:** `epic`'s generic error handler is restored in #213. With `nargs='+'`, outputs whose count matches neither the inputs nor the echoes still reach an `assert`.
