# Issue

**Title:** FIX(pad): accept negative constant fill values such as -.5 or -inf

## Description

Part of #171. This is a , for an issue found while working on that PR.

`pad -b -1` and `-b -1.5` already worked, because `core/cli.py`'s `istag` treats `-<digit>` as a number. Constants whose second character is not a digit, such as `-.5` and `-inf`, were read as tags, so `-b` failed with "Expected a value for tag -b".

**Fix (pad-local):** the `-b` branch of `pad/parser.py` now takes the next argument as the value whenever it parses as a float. Otherwise it falls back to `cli.check_next_isvalue`. A more general fix in `core/cli.py`, covering every command, is being prepared in a separate PR.

**Docs:** a separate writer subagent updated `pad.md`:
- any number, negative ones included (`-1`, `-0.5`, `-.5`, `-inf`), is accepted as the fill value;
- `-b` applies a single boundary condition to all axes.

**Tests:** three new tests in `nitorch/tests/test_cli_pad.py`.
- `test_pad_bound_negative_constant` uses `-1`, `-1.5`, `-.5`, `-1e-3` and `2.5`. It checks that the data are unchanged and that the border equals the value.
- `test_pad_bound_negative_parse` uses `-1`, `-.5` and `-inf`, and checks that a following `-o` is still parsed.
- `test_pad_bound_missing_value` checks that `-b -o out.nii` is still an error.

Before the fix, 3 cases fail. After it, all 28 tests in the file pass.

**Not changed:** per-axis boundary conditions. `-b` has always taken a single value, and `-b -1 replicate` is rejected with a clear error. Supporting per-axis bounds would be a new feature.
