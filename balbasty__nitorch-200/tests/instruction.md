# Issue

**Title:** FIX(reslice): channel ranges, optional -p, shooting params, -k on output grid, --log/--logit

## Description

Part of #171. I reproduced all six bugs before fixing them.

1. **`-c` ranges.** `0:2` failed with "Channel list should be a list of integers". The new helper `channel_index()` turns indices and Python-style ranges into a flat list of channels: `0:2`, `:2`, `1:`, `::2`, negative bounds, and mixtures such as `-c 0:2 2`. It is applied after the data is reshaped to (X, Y, Z, C), so `-c 0` on a 3D volume no longer picks from a spatial axis.
2. **`-p`** used to require a value. A bare `-p` now means yes.
3. **Shooting parameters from the JSON file** were read but never used.
   - `register`'s `nonlin.penalty` (absolute, membrane, bending, lame), `factor`, and `steps`/`fast` when present now reach `spatial.shoot`, together with the voxel size.
   - Three copies of this code are merged into `exponentiate_transforms`, which filters the keys.
4. **`-k`** now counts and places blocks over the **output** grid.
   - It also fixes `UnboundLocalError: grid` with `-t` when the chunk was larger than the output.
5. **`--log`** is applied once. The chunked and whole-volume paths share the same transforms and the same clamp floor.
6. **`--logit`**: logit and softmax now run across channels (`dim=0`), for both the explicit and the `implicit` form.

**Docs:** a separate writer subagent updated `reslice.md`:
- the shooting warning is removed;
- the `-p`, `-c` and `--logit` rows are updated;
- the "Known limitations" list now keeps only the caveats that are still true.

**Tests**
- The new `nitorch/tests/test_cli_reslice_options.py` has 31 tests, covering every item with and without `-k`. On `master`, 24 fail and 7 pass; with this PR, all 31 pass.
- Together with `test_cli_transform_options.py` and `test_cli_reslice.py`: 39 passed.

**Behaviour changes**
- Velocity fields that come with a JSON file are now integrated with the stored regularisation, so results differ from before.
- `-c` follows Python slicing semantics, and an out-of-range selection gives a clear error.

**New issues noticed, not fixed** (added to #171):
- With `-k`, the `--clip` range and the `--log`/`--logit` floor are computed per block.
- With `-k`, spline prefiltering for orders ≥ 2 runs per block, which gives small differences.
- With `-v2` and a JSON file, the velocity is halved before shooting, which is questionable as a square root for geodesic shooting.
- `register` does not save the shooting `steps`.
