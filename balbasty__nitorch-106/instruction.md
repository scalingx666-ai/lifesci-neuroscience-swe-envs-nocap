# Issue

**Title:** FIX(register): center-of-mass init and resliced output for mov/fix position

## Description

## Summary

Part of the `nitorch register` audit fix series (group D).

**`@affine -i com` gave a wrong translation** (`nitorch/tools/registration/objects.py`, `Image.get_center_of_mass`)
- Without a mask it crashed with `UnboundLocalError` because `den` was never assigned. The CLI usually builds a mask from `--missing`, so this path rarely ran.
- With a mask it returned the voxel-space sum `sum(I * x)` divided by the mask volume. That is not weighted by normalised intensity and it is in voxel coordinates, not world coordinates. On a synthetic pair with a known shift of (5, -3, 2) mm, the CLI produced (0.43, -0.82, -0.41).
- It now returns the **world (RAS)** centre of mass. Intensities are made non-negative by subtracting the per-channel minimum (computed within the mask), and each channel is normalised to unit mass. It uses the preview image, i.e. the image before MIND features or discretisation. Non-finite values are ignored. If the image is constant, it falls back to `get_center()` (the FOV centre). Marginal sums avoid allocating a full `(*spatial, D)` grid.
- The conventions match `-i fov`: the affine maps fixed world to moving world, and the translation is `com_mov - com_fix`. The init code in `cli.py` is unchanged.

**`-r` resliced output applied the affine twice for `@affine -p mov|fix`** (`nitorch/tools/registration/pairwise_postproc.py`, `warp_one_image`)
- The check was `if affine.position[0].lower():`, which is always true, so the affine was squared for every position. Only the symmetric position should be squared, because there `AffineModel.exp` returns `sqrtm(A)`. The fix is `== 's'`. This matches how the LTA output is written in `cli.py`. Symmetric output, header-only (`-o`) outputs and the nonlinear path are unchanged.

## Tests

## Found, not fixed here

- `cli.py` `-i fov|com`: the per-loss weight is `0.5 * (Size(fix.shape[1:]).numel() + ...)`, where `fix` is the centre vector, not the image. So every weight is 1, a plain average over losses and pyramid levels. This is harmless now that the centres are in world space, but it is probably not the intended weighting. `affine_init = torch.eye(4)` is also hard-coded to 3D.
- `Image.get_center()` (`-i fov`) casts the affine to the image dtype. For integer (label) images this truncates the affine.
- `warp_one_image(reslice=True)` with no affine and no nonlin would raise an `AttributeError` on `affine.position`. Through the CLI this is only reachable when there is no transform at all.
