# Issue

**Title:** FIX(topup): readout errors, no-args/unknown subcommand, debug print, options before inputs

## Description

Part of #171. This is a , for issues found while working on that PR.

1. **Readout letters.** When no letter in `-r` matched the image, `get_readout` returned the string unchanged, and `readout > 0` raised a `TypeError`. It now raises a clear `ValueError` that names the `-r` value and the image layout (e.g. RAS) and lists the valid letters.
2. **No arguments / unknown subcommand.**
   - With no arguments, or with `-h`/`--help`, `topup` prints the top-level help.
   - An unknown subcommand is now a `ParseError` raised before any parsing, so the command prints the help and then `[ERROR] Unknown subcommand …`. Before, the input was first parsed with `parser_apply`.
   - Related bug: `nitorch topup` calls `cli([])`, and `args or sys.argv[1:]` turned that empty list back into `['topup']`. This now uses `sys.argv[1:] if args is None else list(args)`.
3. **Debug print.** The bare `print(sd.item())` for `-l mse` is now `Noise SD: …`, printed only at `-v 2` or higher.
4. **Options before the inputs.** `cli.CommandParser` reads positionals before options, so *any* option placed before the inputs used to fail. With the optional-value flags from #203, a flag placed there also took the first file as its value.
   - `bool_or_str` now accepts only yes/no/true/false/1/0/on/off, in any case. When the converter rejects a token, the flag is treated as bare and the token is left in place.
   - A small, topup-only `CommandParser` subclass moves leading options, with only the tokens they actually use, to after the positionals. `core/cli.py` is not changed.
   - Result: `fit -d pos.nii neg.nii` reads pos and neg as inputs, with diffeo=True. The same goes for `--diffeo`, `-j`/`--modulation`, and `apply -d field.nii`.

**Docs:** a separate writer subagent updated `topup.md`:
- the option order and the allowed flag values;
- a caveat that list-valued options placed before the inputs still consume them, for example `apply -p pos.nii field.nii`;
- the `-r` letters;
- the behaviour with no arguments or an unknown subcommand;
- the noise SD at `-v 2`.

**Tests:** `nitorch/tests/test_cli_topup.py` now has 48 tests, and all pass. With only the code changes stashed, 16 of the new tests fail.

**Behaviour changes**
- Options can go before the positional inputs.
- After `-d`/`-j`/`--modulation`, a value that isn't a boolean word is no longer taken as the flag's value.
- `nitorch topup` with no arguments prints the help.

**New issues noticed, not fixed** (added to #171):
- Errors raised inside `main_*` are not caught by `cli()`, because the catch-all handler is commented out, so the user sees a traceback.
- A list option placed before the positionals still consumes them; this is inherent to `nargs='*'`.
