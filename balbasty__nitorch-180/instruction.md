# Issue

**Title:** compose: support -l2/-v2 square transforms; robust sqrtm

## Description

## Summary

- **`nitorch compose`**: add `-l2/--linear-square`, `-v2/--velocity-square` and inverse forms (`-il2`, `-iv2`, `--{linear,velocity}-{square-inverse,inverse-square}`), mirroring `nitorch reslice`. The file holds the square of the transform; its square root is applied (affine: matrix sqrt; velocity: halved before exponentiation).
- **`-d2`/`-id2`** (squared displacement fields) are now explicitly rejected with a `ParseError` in both `compose` and `reslice` (reslice previously accepted and silently ignored the square flag).
- **New `nitorch.core.linalg.sqrtm`** (`nitorch/core/_linalg_sqrtm.py`): batched, pure-torch, float64 scaled product-form Denman–Beavers iteration + up to 2 Newton refinement steps (N ≤ 16). Raises `ValueError` when no real principal root exists (real eigenvalue ≤ 0: reflections, 180° rotations, …), on non-convergence, or on large residual. Keeps homogeneous affines' last row exactly `[0,…,0,1]`. Replaces `expm(logm(A) * 0.5)` in both `reslice` and `compose`, which lost precision (scipy round-trip, float32) and silently returned garbage when `logm` went complex.

## Behaviour change
`-l2` inputs with no real principal square root (det ≤ 0, or negative real eigenvalues e.g. large rotation + anisotropic scaling) now raise instead of producing a wrong transform.

## Validation
- New `nitorch/tests/test_linalg_sqrtm.py` (residual vs scipy, homogeneous last row, float32/batch shapes, reflection raises); `test_cli_transform_options.py` and `test_linalg_logm.py` pass.
- 1000 random 4×4 affines (double): max relative residual ‖S·S − A‖ 1.6e-14 (scipy: 2.3e-13).
- End-to-end on synthetic volumes: `compose -l2 A` ≡ `-l sqrtm(A)` (1.2e-7, float32 I/O), `-v2 V` ≡ `-v V/2` (exact), inverse and mixed forms match.
