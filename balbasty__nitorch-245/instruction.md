# Issue

**Title:** svf: cheaper, leaner exp_backward; shared small-matrix linalg

## Description

## Summary
This is the `exp_backward` item of #158. `exp_backward` pushes the gradient and Hessian through the scaling-and-squaring steps of an SVF, and it was the largest cost of an SVF iteration. Each squaring step did:
- four pulls: gradient, Hessian, the D×D Jacobian, velocity;
- batched LU for the 3×3 determinants (plus one inverse before the loop);
- batched matmuls for the matrix-vector products.

> **Now also contains #255** (#157: `maybe_script` / `maybe_compile` / `maybe_jit` for leaf kernels), which was merged into this branch. CI passes on both torch 1.13.1 and 2.5.1 with it included.  for that part.

Two commits (plus #255):

1. **PERF(svf): cheaper and leaner `exp_backward`.**
   - The Jacobian of the squared displacement comes from central finite differences (`_disp_jacobian`) instead of composing Jacobians, which required pulling all D×D components. With circular boundaries it is written into one buffer reused across steps; other boundaries use `grid_jacobian`.
   - Closed-form small-matrix operations replace LU and `bmm`. The initial inverse is never formed: the system is solved by Cramer's rule, with cofactors computed on the fly.
   - The transformation `id + vel` is built once per step instead of once per pull.
   - The pulls stay **separate**. Fusing them into one multi-channel pull was not faster and used more memory, consistent with the constraint in #154.
2. **REFACTOR(linalg): shared closed-form helpers.** `_shoot` already had private 2×2 and 3×3 determinant and inverse functions, and the first commit added a second set. Both are now in `nitorch/core/_linalg_small.py`, the general (non-symmetric) counterpart of `_linalg_sym`, exported by `nitorch.core.linalg`:
   - `small_det`, `small_adj`, `small_inv`, `small_solve`, `small_matvec`;
   - `(..., D, D)` layout, closed forms for D ≤ 3, `torch` above;
   - `_shoot._inv` uses them and keeps its own small determinant regulariser. The Greens kernels are **bitwise identical** to master (2D and 3D, float32 and float64, three Lamé settings).

## Effect
192³, 4-thread CPU, without #255. With #255 on torch ≥ 2, `exp_backward` is about 20% faster again in steady state; .

| | master | this PR |
|---|---|---|
| TS, grad + hess | 127 s | 63 s |
| TS, grad only (every line-search trial) | 92 s | 27 s |
| C, grad + hess | 41.5 s | 26 s |
| C, grad only | 22 s | 13 s |

Peak memory over the inputs is lower in every case:

| | master | this PR |
|---|---|---|
| TS, grad + hess | +2960 MB | +2176 MB |
| TS, grad only | +2555 MB | +1744 MB |
| C, grad + hess | +2060 MB | +1815 MB |
| C, grad only | +1490 MB | +921 MB |

**Accuracy.** The finite-difference Jacobian is a different discretisation, so outputs differ from master by about 1e-5 on smooth fields and up to about 5e-3 on rough ones. What matters is the distance to the exact gradient (autograd through `exp_forward`), and it is unchanged: relative errors of 0.0426 vs 0.0426 (3D), 0.0704 vs 0.0703 (2D), and so on, over 8 configurations.

Side finding, not changed here: with `inverse=True`, `exp_backward` is 8–26% off the exact gradient, compared with 3–7% for the forward direction, on master as well.
