# Issue

**Title:** FIX(spatial.shoot_approx): unpack forward args by name; fix backward

## Description

Part of #171.

`shoot_approx`'s backward pass failed for every flag combination, so no gradient ever reached `vel`. The forward output was always correct.

## Cause (`_ApproximateShoot` in `nitorch/spatial/_shoot.py`)
- **Indexing:** `forward` read `args[7]`/`args[8]` as `return_inverse`/`displacement`, but those positions hold `voxel_size`/`return_inverse`. With the default `voxel_size=1` it always thought an inverse was returned:
  - `return_inverse=False`: it saved `outputs[0]`, the first batch slice instead of the grid. `backward` then raised `ValueError: not enough values to unpack`.
  - `return_inverse=True`: `backward(ctx, grad_output)` takes a single gradient and raised `TypeError: backward() takes 2 positional arguments but 3 were given`.
- **Hidden by those crashes:**
  - With `displacement=True`, the saved tensor was a displacement but was used as a coordinate grid in `_push_grid`.
  - The approximate gradient had the wrong sign. Since `shoot` returns φ ≈ id − v and φ⁻¹ ≈ id + v, the gradient is approximately `−push(g, φ) + g_inv`; the old code computed `+push(g, φ) − g_inv`. A finite-difference check confirmed the sign. Because the backward pass never ran, nothing depended on the old sign.

## Fix
- `forward` unpacks its arguments by name and passes them to `shoot`.
- It saves only the forward transform, as a coordinate grid; with `displacement=True` the identity is added first.
- `backward(ctx, *grad_outputs)` computes `−push(g, grid)`, adds the inverse's gradient when there is one, and handles `None` gradients.
- The public signature and the forward results are unchanged.

## Impact
No CLI path uses `shoot_approx`. It is reached only through `nn`:
- `GeodesicShoot(approx=True)` (`nitorch/nn/modules/spatial.py`);
- the registration module with `shoot='approx'` (`nitorch/nn/modules/registration.py`).

Training through either path crashed on the first backward pass.

## Tests
New file `nitorch/tests/test_shoot_approx.py` covers 2D and 3D, with `return_inverse` and `displacement` each `False` or `True`:
- the forward output equals `shoot` exactly;
- the approximate gradient is close in direction to a finite-difference gradient of `shoot`: cosine similarity above 0.8 (measured 0.89–0.97).

`gradcheck` isn't used because the backward pass is approximate by design.

`pytest nitorch/tests -k shoot`: 102 passed, 1 skipped. Before the fix, the 8 new cases failed (94 passed, 1 skipped).

Not fixed here (listed in #171): `shoot` under autograd fails with "Output 0 of Permute is a view and is being modified inplace". This happens with `displacement=True` as well, not only `displacement=False`. It doesn't affect `shoot_approx`, which runs `shoot` without an autograd graph.
