# Issue

**Title:** FIX(register): -d, bare -o/-r, prod/squeezed losses, lcc stride tag, mse -w auto

## Description

Part of #171. I reproduced all five items before fixing them.

1. **`-d/--dim` was ignored**, because `dim = 3` was hard-coded.
   - Real 2D support needs work in the registration engine: `map_image` returns a 4×4 orientation matrix, and the affine models, the LTA writer, `get_spaces`/pyramid and `warp_images` are all 3D-only.
   - So `-d` is now **validated**: only 3 is accepted (the default). Any other value is a `ParseError`, raised before any image is read, which points to `-2d` in `@affine`/`@nonlin` for single-slice data.
   - Plan for real 2D, if wanted:
     - slice the orientation matrix to (D+1)×(D+1) in `map_image`;
     - thread `dim` through `get_spaces`, `preproc_image`, `make_affine` (2D Lie bases), `make_nonlin` and `warp_images`;
     - decide how to write a 2D affine to LTA.
2. **A bare `-o` or `-r true`** on `@@fix`/`@@mov` became `True`, and the command crashed after the fit.
   - They now map to the default templates (`{dir}{sep}{base}.moved{ext}` / `.resliced{ext}`), and `false` maps to False.
   - A new `check_options()` formats every output template before the fit, so a bad template fails immediately.
3. **`prod`/`squeezed`** were a wiring bug, so they are now fixed rather than rejected.
   - `prod` is an alias of `dot`, and `squeezed` of `sqz`. The old alias went the wrong way.
   - A missing `sqz` weight now keeps the class default of 1 instead of passing `lam=None`.
4. **`lcc`/`lgmmi --stride`** lost its short tag `-s`, which clashed with `--symmetric`. `--stride` still works.
5. **`-w auto`** for `mse`/`mad`/`tuk` now becomes `None`, which those losses treat as "estimate the weight from the data". Other non-numeric values are rejected at parse time.
