# Issue

**Title:** FIX(register, reslice): keep all affines in the minimal-reslice grid

## Description

## Summary

The default minimal-reslice output now keeps the whole affine in its orientation matrix (header), not just the affines on one side. This applies to `register -o` (the `.moved` file) and to `nitorch reslice` without `-t`. Only the near-identity nonlinear residual gets resampled, which is more robust when the affine contains a large shift.

### `register -o` (`nitorch/tools/registration/pairwise_postproc.py`)
- **Before:** the affine went into the output header only when it sat on the image's own side of the nonlinear warp (`moving`/`symmetric` for the moving image, `fixed`/`symmetric` for the fixed image). Otherwise the whole affine was resampled into the voxels, and a large shift could push the image out of its own field of view.
- With affine-only registration, the moving image under `-p fix` (and the fixed image under `-p mov`) came out unchanged, with its original header. The affine was dropped entirely.
- **Now:** the output header is always `inv(A) @ mov_affine` for the moving image and `A @ fix_affine` for the fixed image, where `A` is the full affine whatever its position (squared for `symmetric`).

### `nitorch reslice` without `-t` (`nitorch/cli/registration/reslice/main.py`)
- **Before:** only the first transform in the chain was absorbed, and only if it was linear. For example, `reslice fix.nii -iv vel.nii -l affine.lta` ignored the affine when building the output grid.
- **Now:** every linear transform in the chain goes into the output header. The `-t` help text describes this.

### Behaviour change
In these cases, the minimal-reslice outputs now have a different header than before. They show the same thing in world space.
