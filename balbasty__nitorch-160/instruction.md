# Issue

**Title:** Fix LGMMH ignoring masks (masked local GMM fit)

## Description

## Summary
`register` passes `mask` (fixed mask times the warped out-of-FOV mask) to every loss, but `LGMMH._call` dropped it (`kwargs.pop('mask')  # TODO`). That breaks the loss contract that MSE/GMMH/LCC follow, so out-of-FOV and masked-out voxels skewed the local fit, the value, the gradient and the Hessian.

This PR adds a masked local fit (`LocalMask` in `utils_gmm2.py`):
- Each patch gets a weight equal to its in-mask fraction `frac = local_mean(mask)`. The local log-likelihood of a voxel is now a convex combination of patches weighted by `frac` (`bwd(s*frac) / bwd(frac)`). A patch that is entirely masked out contributes nothing and produces no NaN.
- The M-step uses the matching adjoint voxel weights `mask / bwd(frac)`, so EM minimises the in-mask average nll. Masked voxels add nothing to the local sufficient statistics.
- The global initialisation (`fit_gmm2`) and the value are restricted to the mask, and the value is normalised by the in-mask count. The gradient and Hessian are multiplied by the mask, so they are exactly 0 outside it.
- With no mask, the old code path runs unchanged (the new code only runs when `mask is not None`).

## Tests
New tests in `nitorch/tests/test_register_gmm.py`. They fail on master, where `lgmmh` has no `mask` argument and `LGMMH` drops it:
- Changing the outliers in the masked-out region does not change the value, gradient or Hessian. The gradient and Hessian are exactly 0 there. (slow)
- Directional FD check of the gradient with a mask, plus a check that the Hessian has the right magnitude. (slow)
- Patches that are entirely masked out (Gaussian and square kernels) give finite results.
- No mask still runs the old path. `LGMMH` passes `mask` through.
