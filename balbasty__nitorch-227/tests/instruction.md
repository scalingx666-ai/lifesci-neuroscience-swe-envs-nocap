# Issue

**Title:** FIX(epic): check the number of outputs before fitting

## Description

Part of #171. This is a , for an issue found while working on it.

**Bug (reproduced):** a wrong number of `-o` outputs was only caught after `epic()` had run the whole fit. The check then raised a `ValueError`, which the generic handler printed as `[ERROR] There should be either one output file, …`, without the usage text. The `assert len(output) == len(fit)` after that check could never fail.

**Fix:** a new `check_outputs(input, output)` runs at the very start of `main`, before the readout lookup and before `epic()`. It counts the echoes in each input with `map_files(inp).shape[0]`, which reads only the header, not the data. A bad count raises:

```
ParseError: Expected 1 output, or one per input (N), or one per echo (E); got K.
```

The CLI then prints the help, followed by the error, and returns 1. The late `ValueError` block and the dead `assert` are removed.

Accepted counts (unchanged):
- **1 output.** If it contains `{base}` and there are several inputs, it is repeated, giving one file per input. If it contains `{n}`, it gives one file per echo. Otherwise it gives a single 4D file with all echoes.
- **One per input.** This takes priority when the number of inputs is also the number of echoes.
- **One per echo.** Echoes are counted over all inputs, so a 4D input contributes all its volumes.

**Also fixed:** the per-input save branch used `[*io.map(inp).shape, 1][3]` to count echoes. For 5D `(X,Y,Z,1,C)` inputs that gave 1, so the output was split wrongly. It now reuses the echo counts from `check_outputs`.

**Docs:** a writer subagent updated the Output files section of `docs/cli/reference/qmri/epic.md`:
- `{n}` is the input index when there is one output per input;
- echoes are counted over all inputs;
- the count is checked before anything is computed, and the page gives the error text.

**Tests** (`nitorch/tests/test_cli_epic.py`):
- 3 bad counts, each checking that a `ParseError` is raised, that its message gives N, E and K, and that `epic` is never called;
- the CLI message and the exit status 1;
- the 5 accepted cases, checking the saved names and shapes.

Before the fix 4 fail; after it, all 31 pass.

**New bugs noticed, not fixed (added to #171):**
- Two 3D inputs with the default reverse-echo synthesis and no `-e` crash in `synthesize_neg` (`tools/denoising/epic.py`) with `IndexError: index -2 is out of bounds`, because synthesis needs at least 2 echoes of each polarity.
- `map_files` has a repeated condition: `files.dim == 5 and files.shape[3] == 1 and files.dim == 5`.
- `-r/--reversed` files are not counted among the outputs. I assume the fit returns only the forward echoes, but this has not been checked.
