# Issue

**Title:** [REF] Use _round2 for KDA's approximate-null tie-break

## Description

Closes # N/A — no issue. Found while comparing NiMARE's null-distribution binning against GingerALE 3.0.2, JALE and CANlab MKDA.

Changes proposed in this pull request:

- `KDA._compute_null_approximate` bins the convolved scores with `nimare.utils._round2` instead of `np.round`, so ties break away from zero — the rule `nullhist_to_p` already uses when it reads a statistic off this same grid. A score has to be read out of the bin it was counted into; `np.round` sends an exact half-step to the *even* bin. This is the same class of mismatch #1147 fixed for the ALE path.

### This is a no-op today, and that is the honest framing

Please don't read this as a bug fix. While verifying, I found the tie case is not merely rare but **unreachable**: the bin centres are exact multiples of the step, so every `(c_i + c_j) / step` is an exact integer — there is no fractional part for a tie-break to act on, whatever the kernel value.

```

  max abs diff   : 0.000e+00

=== Tie reachability in KDA's convolution ===
  exact .5 ties encountered   : 0
  np.round vs _round2 disagree: 0

=== Grid arithmetic ===
  max deviation from integer  : 0.000e+00
```

What makes it worth merging anyway is the comment above the grid construction, which anticipates weighting support. Weighting is exactly what would break the integer-multiple property and let the two rounding rules diverge silently. Reviewers who would rather not carry a no-op change should feel free to close this — the argument for it is forward-looking only.

### No test, on purpose

With ties unreachable, a behavioural assertion cannot fail, and duplicating the rounding expression in a test would restate the implementation rather than check it. The scale-invariance test added with #1145 still covers the reachable behaviour. If you'd prefer the convention pinned explicitly, the clean way is to extract the lookup into a named helper (as ALE did with `_nearest_bin`) and unit-test that — happy to do it that way instead.

### Context: what the other packages do

For the record, since it motivated the change — every reference implementation assigns a value to the **nearest bin centre**, never a floor:

| Package | Rule |
|---|---|
| GingerALE 3.0.2 | `org.brainmap.meta.HistogramQueue.getBin` → `(int)Math.round(d / binSize)`; centres at `binSize * n`. Ties up. Used for the per-study histogram, the convolved score, *and* the p-value lookup. |
| JALE | `np.round(score * step)` and `np.round(ale * step)`; per-study histogram uses `np.digitize` against edges offset by half a step, which is nearest-centre by another name. |
| CANlab MKDA | Does not bin. Monte Carlo null stores raw per-iteration max statistics; thresholds via `prctile(maxprop, 95)`. |

Java's `Math.round` breaks ties away from zero for non-negative input, so `_round2` matches GingerALE's convention as well as `nullhist_to_p`'s.
