# Issue

**Title:** FIX(denoise): pass -x through, import warnings, keep squeezed input

## Description

Part of #171. I reproduced each bug before fixing it.

1. **`-x`/`--optim`** (`cg`, `relax`, `fmg`, `fmg+cg`, `fmg+relax`) was parsed but never forwarded, so CG was always used. `_cli` now passes `optim=` to `denoise()`.
   - **Note:** `tv.denoise` still forces `cg` for reweighting iterations 1–9. This is existing behaviour, left unchanged. So `relax` only takes effect from iteration 10 on, while the FMG variants apply at every iteration. The docs now say so.
2. **`warnings` was not imported**, so `--gpu` without CUDA raised a `NameError`. It now warns and falls back to the CPU.
3. **`ensure_4d`** threw away the result of `squeeze`, and then always raised. So any input with more than 4 dimensions failed. It now keeps the squeezed array, and raises only when no singleton dimension is left. Only dimensions from index 3 up are squeezed, so singleton spatial axes are kept.

**Docs (`denoise.md`)**
- The `-x` caveat is replaced by what each solver choice does.
- Documented the `--gpu` fallback and the squeezing of extra singleton dimensions.

**Tests**
- The new `nitorch/tests/test_cli_denoise.py` has 4 fast tests; the solver is monkeypatched so it never runs:
  - `-x relax` reaches the solver;
  - `-x fmg+cg` reaches the solver;
  - `--gpu` without CUDA warns and falls back to the CPU;
  - a 5D (4,5,6,1,2) input runs end to end.
- All 4 fail before the fix and pass after it.
